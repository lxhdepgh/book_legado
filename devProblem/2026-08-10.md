# 2026-08-10 已解决问题

## 保存第三方历史源码后 pytest 误收集其测试

- 现象：`base_history/rarfile` 中的上游测试被项目 pytest 自动收集，并因上游主分支与当前固定 pip 版本包结构不同而在收集阶段报错。
- 原因：pytest 默认递归扫描所有 `test` 目录，历史源码目录此前没有排除规则。
- 方案：新增 `pytest.ini`，仅将 `base_history` 设为 `norecursedirs`；项目根测试和 `tests` 仍完整收集，历史源码及真实 RAR 夹具继续用于显式差分测试。

## 目录 formatJs 未执行

- 现象：带 `ruleToc.formatJs` 的外部书源无法按章节索引或共享计数格式化标题。
- 原因：此前根据不完整参照误判该字段没有官方调用点。
- 官方依据：Legado `3.23.110211` 的 `BookChapterList.analyzeChapterList()` 在目录去重和排序后执行该脚本。
- 方案：补齐 `index/chapter/title/gInt` 上下文和跨章节 `gInt` 回写。
- 防复发：两章目录测试断言得到 `One-1-1`、`Two-2-2`。

## 旧式字符串规则对象导入失败

- 现象：规则字段是 JSON 字符串时，导入后仍为字符串，运行链路调用 `.get()` 失败。
- 原因：当前模型只接受字典；Legado 的规则反序列化器同时接受 JsonObject 和 JsonPrimitive。
- 方案：导入六类规则字段时解析字符串 JSON；非法或非对象结果回退为空规则。
- 防复发：加入合法字符串规则和非法字符串规则测试。

## 长分页被静默截断

- 现象：目录超过 30 页或正文超过 20 页时，后续页面永远不加载。
- 原因：Python 实现加入了官方没有的固定循环上限。
- 方案：依靠已访问 URL 集合和空下一页终止，支持任意有限分页长度。
- 防复发：22 页正文测试必须包含最后一页。

## 三井号正则语义错误

- 现象：`##match##replacement###` 保留了首个匹配之外的全文。
- 原因：误实现为 Python `re.sub(..., count=1)`。
- 官方语义：先取得第一个匹配片段，再在片段内替换；无匹配返回空。
- 方案：按 `AnalyzeRule.replaceRegex()` 对齐，并让列表提取路径复用同一实现。
- 防复发：覆盖首匹配返回和无匹配返回空。

## 阅读页重复导航且滚轮续章失效

- 现象：页面上部已经提供上一章、详情目录和下一章，正文底部仍重复显示相同按钮；滚动到底部只保存位置，不再进入下一章。
- 原因：移动端层级重构增加顶部工具栏时保留了旧底部导航，但后续持久化滚动逻辑覆盖了原来的底部续章分支。
- 方案：删除底部导航控件；在保存滚动位置后恢复底部阈值检测和下一可读章节的连续加载。
- 防复发：测试断言正文列表只包含标题、分隔线和正文，并断言连续两次相同底部滚动事件只调度一次下一章。

## AnalyzeUrl 重试和字段编码偏差

- 现象：未声明 `retry` 的请求仍会额外尝试两次；GBK 等书源的中文查询值未按字段字符集编码。
- 原因：本地实现使用了自定义重试默认值和整段请求体编码，没有复现 `UrlOption` 与 `analyzeFields`。
- 方案：默认重试数改为 0，保留显式非负值；对普通查询和表单逐值执行对应字符集的 `quote_plus` 等价处理，已编码值保持原样。
- 防复发：加入默认、显式、负数及非法重试值测试，以及 GBK 中文和已有百分号编码测试。

## Jayway JsonPath 尾部函数缺失

- 现象：过滤和切片可用，但 `$.items.length()`、`.first()`、`.keys()` 等规则总是返回空。
- 原因：`jsonpath-ng` 不实现 Legado 历史版所依赖的 Jayway 2.8 尾部函数。
- 方案：在标准路径求值后增加 Jayway 尾部函数层，覆盖统计、集合、索引和拼接函数，并按官方异常抑制配置返回空结果。
- 防复发：对 12 类尾部函数、负索引、越界索引及对象键集合加入回归断言。

## URL 字符集错误地覆盖响应解码

- 现象：书源用 GBK 编码搜索参数、服务端返回 UTF-8 正文时出现乱码。
- 原因：把 `UrlOption.charset` 同时用于请求字段和响应正文；历史 `AnalyzeUrl` 只用它编码字段。
- 方案：响应独立依据 HTTP 字符集、HTML meta 和内容检测解码，同时移除 UTF-8 BOM。
- 防复发：覆盖 UTF-8 HTTP 字符集、无头 BOM、GBK meta 三类响应。

## JSONPath 标量字符串格式不兼容 JVM

- 现象：布尔值变成 `True/False`，对象变成 Python 字典文本，`null` 变成 `None`。
- 原因：提取层直接调用 Python `str()`。
- 方案：增加统一的 Legado 值字符串化，输出 Java/Jayway 等价格式。
- 防复发：覆盖布尔、null、对象和内嵌模板四类结果。

## 内嵌 JSONPath 遇到右花括号或过滤符时截断

- 现象：`{$.items[?(@.text == '}')].text}` 无法求值。
- 原因：简单正则不能平衡引号和括号，同时通用规则拆分把 JSONPath 的 `@` 当成 HTML 属性分隔符。
- 方案：复现历史 `RuleAnalyzer` 的平衡扫描；内嵌 JSONPath 直接进入 JSON 引擎，不经过 HTML 拆分。
- 防复发：加入过滤字符串包含 `}` 的完整模板回归用例。

## getString 未执行 HTML4 实体反转义

- 现象：JSON API 返回的 `&amp;`、`&#x4E66;` 原样进入书名、简介或 URL。
- 原因：Python 提取层缺少历史 `AnalyzeRule.getString` 最终的 `StringEscapeUtils.unescapeHtml4` 阶段。
- 方案：在 Python 字段提取流程结束后统一执行 `html.unescape`，再进行 URL 绝对化。
- 防复发：覆盖普通 JSONPath、内嵌模板和带实体查询参数的相对 URL。

## Jsoup 属性列表保留重复和空值

- 现象：相同章节或分页链接由多个节点给出时会重复进入后续流程。
- 原因：Python 列表推导未复现 `getResultLast` 的 `isBlank` 与 `contains` 判断。
- 方案：属性提取按文档顺序跳过空值并有序去重。
- 防复发：覆盖重复链接、空链接、缺失属性和不同链接组合。

## 裸 XPath 元素输出 Python 对象描述

- 现象：`//p[@class='x']` 选中元素后得到 `<Element 'p' at 0x...>`，后续正则和 JS 无法处理正文。
- 原因：elementpath 返回 `ElementTree.Element`，字段层直接调用 Python `str()`。
- 方案：按 JXNode `asString()` 语义将元素序列化为实际 XML/HTML 标记文本。
- 防复发：断言裸 XPath 元素包含标签与正文且不包含对象地址。

## ZIP 与 XML 响应处理缺失

- 现象：ZIP 正文被按压缩字节解码为乱码；无声明 XML 与 Legado 返回内容不同。
- 原因：aiohttp 处理传输压缩但不展开 `application/zip` 文件，且 Python 网络层没有 Legado 的 XML 后处理。
- 方案：用 `zipfile` 读取首个非目录项；为 XML 媒体类型补充缺失声明，同时保留原始响应字节。
- 防复发：覆盖含目录和多个文件的 ZIP、缺声明 XML、已有声明 XML。

## @put 吞掉后续规则且执行顺序错误

- 现象：真实书源的 `@put:{...}\n@js:java.log(baseUrl)` 不执行 JS；同字段 JS 读取不到刚保存的变量。
- 原因：Python 使用第一次 `find("@put:")` 后截取到字符串末尾，并在整个字段结束后才保存变量。
- 方案：按历史正则精确提取 `@put:{...}`，保留其余 SourceRule；在当前规则求值前执行变量保存。
- 防复发：覆盖字段规则和列表规则的 put+JS 后缀，以及 JS 即时读取变量。

## @get 前缀没有进入后续 JavaScript

- 现象：内置书源的 `@get:{img}@js:...` 直接返回包含 JS 源码的文本。
- 原因：变量替换分支将非 `@js:` 开头的结果当成终值，没有继续拆分 SourceRule。
- 方案：识别替换结果中的后续 JS 边界，把前缀作为 `result` 传入 JS；JS 内的 `@get` 则先替换再执行。
- 防复发：分别覆盖 get 前缀接 JS、JS 内嵌 get 两种真实规则形态。

## 正文 HTML 实体反转义时机过早

- 现象：正文中的 `&lt;b&gt;文字&lt;/b&gt;` 提取后立即变成标签，可能被格式化器改变或移除。
- 原因：通用 Python 字段提取统一执行反转义，没有复现正文专用的 `getString(unescape=false)`。
- 方案：反转义选项贯穿字段和递归 JS 管线；正文结构格式化后才反转义可见文本。
- 防复发：断言转义标签最终可见但不参与 DOM 结构识别。

## 未配置分页规则时自动猜测下一页

- 现象：没有 `nextContentUrl` 或 `nextTocUrl` 的书源仍会跟随页面中的“下一页”，存在误并下一章风险。
- 原因：Python 实现加入了历史 Legado 不存在的智能分页回退。
- 方案：移除业务流程中的自动猜测调用，仅消费书源明确配置的分页规则。
- 防复发：页面包含“下一页”链接但未配置规则时只请求当前页。

## 阅读快速路径重新引入 Python JSON 字符串格式

- 现象：基础提取已输出 `true`，但详情/正文快速路径仍输出 `True` 和 Python 字典文本。
- 原因：`_strict_value` 直接对解析结果调用 `str()`，绕过统一兼容转换。
- 方案：所有快速路径复用 `_legado_value_string`。
- 防复发：覆盖布尔、对象和 null 的严格字段提取。

## 固定书籍上限和智能猜测改变官方结果

- 现象：超过 100 条的列表被截断；规则失败时仍可能从页面猜出书籍或字段。
- 原因：Python 引擎为容错加入固定上限与 DOM 启发式，不属于 Legado 规则语义。
- 方案：删除固定截断和默认智能回退，严格消费书源规则结果。
- 防复发：覆盖 125 条书籍结果，以及包含明显书卡/链接/图片但规则未命中的页面。

## 默认目录正文规则和状态作用域不符合官方流程

- 现象：缺少规则时仍能猜出章节/正文；不同书源共享 Cookie；不同引擎绕过同一书源并发限制。
- 原因：Python 实现提供默认 DOM 规则，Cookie 与 concurrentRate 都绑定错误的作用域。
- 方案：严格要求书源规则；Cookie 按 source 隔离；并发预约按 source 全局共享。
- 防复发：严格章节 URL 测试、禁用/跨源 CookieJar 测试、跨引擎 concurrentRate 测试。

## Java 正则仅在部分入口被转换

- 现象：基础 `##regex##replacement` 支持 `$1`，但正文 `replaceRegex`、模板字段和 `@get` 后缀仍直接调用 Python `re`，命名组、`\R`、`\z` 会失败。
- 原因：兼容转换散落在单个帮助函数，没有形成所有书源正则共用的执行层。
- 方案：建立 `java_regex.py`，所有书源提供的正则统一经过 Java pattern/replacement 转换；内部固定 Python 正则保持不变。
- 防复发：同时覆盖字段原始响应与正文阶段的命名组、换行类和绝对结尾测试。

## SourceRule 模式推断与历史源码不同

- 现象：`@XPath:`/`@Json:` 前缀仍留在规则正文，`@get`、模板和 `$1` 组合没有提升到 Regex 模式。
- 原因：Python 原先只按首字符粗略分类，未复现 `SourceRule` 构造过程。
- 方案：统一编译器按历史固定顺序执行前缀处理、put 提取、eval 检测和捕获组模式提升。
- 防复发：为所有显式前缀、插值、捕获组及 allInOne 冒号模式建立编译结果断言。

## Jsoup html 提取错误地隔离 DOM 副作用

- 现象：一个字段执行 `@html` 后，后续字段仍能读取官方已经删除的 script/style。
- 原因：Python 克隆节点，与 `AnalyzeByJSoup.getResultLast` 直接修改 Elements 不同。
- 方案：修改共享 BeautifulSoup 节点后再序列化，并支持 `abs:` 属性前缀。
- 防复发：同时断言 html 输出和原始 root 均已删除脚本与样式节点。

## 目录反转与去重顺序不符合 BookChapterList

- 现象：负号章节规则只反转每一页，重复 URL 按“标题＋URL”保留，和官方最终目录不同。
- 原因：没有复现收集全部分页后“条件反转、URL LinkedHashSet 去重、按 reverseToc 再反转”的固定流程。
- 方案：先合并全部页面，再按 URL 去重并执行官方双反转；同步更新索引和书籍检查状态。
- 防复发：覆盖规则正负号与 reverseToc 的四种组合，并使用同 URL 不同标题验证保留首项或末项。

## URL 规则阶段存在隐藏固定截断

- 现象：超过 32 个模板或 16 个前置 JS 阶段时，尾部规则静默保留且不执行。
- 原因：Python 用固定循环次数防止异常规则无限循环。
- 方案：改用已见完整规则文本检测循环；只要每轮仍产生新文本就继续执行。
- 防复发：使用 40 个连续模板断言全部替换完成。

## Java Unicode property 与字符类交集无法编译

- 现象：`\p{L}`、`\p{P}`、`\p{IsHan}`、`[a-z&&[^aeiou]]` 和 `\G` 在 Python re 中报错或产生错误匹配。
- 原因：这些是 Java Pattern 方言能力，不能直接传给 Python 标准正则。
- 方案：用 unicodedata 生成精确区间，预计算字符类交集，并为 `\G` 保留连续 Matcher 位置。
- 防复发：覆盖中英文 Unicode 分类、交集/排除交集、连续替换及 Java 内联 flags。

## JSONPath 函数中间路径和复合谓词返回空

- 现象：`keys()[0]`、`first().name`、`&&/||` 复合过滤以及 indefinite 单数组匹配无法得到 Jayway 结果。
- 原因：原实现只识别表达式末尾函数，并把所有单个数组结果无条件 flatten；jsonpath-ng 也不接受 Jayway 的完整逻辑语法。
- 方案：增加阶段扫描和独立谓词求值器，按 definite 属性决定数组展开方式。
- 防复发：覆盖函数后索引/属性、括号逻辑、false 值存在谓词、正则组合及 definite/indefinite 对照。

## Jsoup 索引被错误地应用到合并结果

- 现象：两个父节点执行 `@li.0` 只返回第一个父节点的首项。
- 原因：Python 先合并所有父节点的子元素，再执行一次索引；官方 ElementsSingle 对每个父元素独立执行。
- 方案：选择、区间和排除操作移入逐父节点循环，并保持 LinkedHashSet 顺序。
- 防复发：覆盖两个父列表的选择、排除、反转，以及完整负步长/越界真值表。

## replaceRegex 编译失败时错误地保留原文

- 现象：书源使用 `##\\` 删除反斜杠时，Python 正则编译失败后直接返回原文。
- 原因：遗漏了历史 `AnalyzeRule.replaceRegex` 的 `runCatching` 回退；官方会调用 Kotlin `String.replace` 做普通文本替换。
- 方案：正则失败后执行字面量替换，静态审计也把该回退路径视为可执行规则。
- 防复发：用无效正则反斜杠夹具同时断言执行结果和 1,066 源完整审计清零。

## XPath 输入在求值前被 HTML parser 小写化

- 现象：带 XML 声明的 `<Item>` 无法被 `//Item` 命中，namespace 与 CDATA 节点也在进入 XPath 前丢失。
- 原因：响应根节点统一使用 HTML parser；历史 `AnalyzeByXPath` 会对 XML 声明使用 Jsoup XML parser。
- 方案：用标准 DOM 保留 XML 大小写、前缀和特殊节点，再构造共享节点树并向 elementpath 注入 namespace。
- 防复发：覆盖同名大小写元素、XML media type、带前缀节点、CDATA、comment 和 processing instruction。

## XPath html() 返回了外部标签且绝对路径根错误

- 现象：`//div/html()` 返回 `<div>...</div>`，`/html/body/...` 在 HTML 片段上无法命中。
- 原因：Python 把 `html()` 当作 ElementTree 外部序列化，并额外创建了可见的 `document` 根；两者都不同于 JXDocument。
- 方案：构造 HTML document shell，复现 td/tr/tbody 片段包装；分别实现 html、outerHtml、allText、num NodeTest。
- 防复发：同时覆盖内部/外部 HTML、绝对路径、表格片段、扩展运算符、单步兄弟轴和扩展字符串函数。

## XPath num() 仅能用于路径尾部

- 现象：官方示例 `//li[./span/num()>1000]` 在 Python 中无法编译，尾部 num 对 `.69` 和子节点数字也不一致。
- 原因：原实现把 NodeTest 全部当作结果后处理，没有进入 XPath 谓词求值阶段，并错误使用 ownText 与较窄数字正则。
- 方案：向 elementpath 注册 Python 扩展函数，嵌入路径改写为求值期调用；严格采用 v2.5.3 的 allText 与数字模式。
- 防复发：覆盖子节点数字、`.69`、整数/小数返回类型，以及 Java `String.matches` 整串正反匹配。

## ElementTree 改变 JsoupXpath 文本节点顺序并丢失 tail

- 现象：`//h2//text()` 先返回父节点空白和 tail，再返回子节点文本；following-sibling::text 无法取得标签后的 `11`。
- 原因：ElementTree 用 `text/tail` 存储文本，默认 XPath 返回顺序与 JsoupXpath 的 Text NodeTest 深度优先遍历不同；转换顶层节点时还忽略了 NavigableString。
- 方案：保留顶层 text/tail，建立独立深度优先文本节点流与轴事件序列，并按父节点维护文本块位置。
- 防复发：直接迁移 v2.5.3 的豆瓣、issue44、issue52、issue64/65、issue66 参数化矩阵。

## elementpath 的 XPath 2 严格序列参数拒绝官方规则

- 现象：`contains(text(),'页数')` 在元素有多个直接文本节点时抛出“sequence of more than one item”。
- 原因：elementpath 默认 XPath 2 严格模式；JsoupXpath 2.5.3 实现的是 XPath 1 兼容转换。
- 方案：固定 Python XPath parser 开启 compatibility mode，同时保留自定义 NodeTest 与 Java 正则函数。
- 防复发：使用官方豆瓣详情页同时断言页数 `956` 与定价 `139.00元` 的 following-sibling tail 文本。

## 两参数 downloadFile 错误地从 URL 后缀推断文件类型

- 现象：`java.downloadFile(hex, "https://host/book.zip")` 在 Python 中成功写入，而固定源码会因 `AnalyzeUrl.type == null` 返回空字符串。
- 原因：复用了单参数下载的 `UrlUtil.getSuffix` 逻辑，但历史两参数重载只接受 URL option JSON 中的显式 `type`。
- 方案：两个重载分开确定文件名；十六进制重载缺少显式 type 时立即返回空字符串。
- 防复发：同时断言普通后缀返回空、`,{"type":"txt"}` 成功，并让 ZIP/7z/RAR 真实夹具全部使用历史 option 形式。

## AnalyzeUrl retry 的触发条件实现反向

- 现象：Python 遇到连接超时会按 retry 重试，遇到 HTTP 503 却立即抛错；固定源码行为正好相反。
- 原因：按常见网络客户端习惯实现了容错，没有逐行遵循 `OkHttpUtils.newCallResponse` 的 `response.isSuccessful` 循环。
- 方案：HTTP 非成功响应继续下一次请求并在最终仍返回响应；IOException/连接/断开/超时立即传播。
- 防复发：urllib 与 aiohttp 两条路径分别断言“503 后 200 请求两次”和“连接异常即使 retry=3 也只请求一次”。

## 把 Jayway Map 当成 JSON 文本并给 keys() 增加了索引能力

- 现象：`$.item` 输出 `{"id":1}`，`$.keys()[0]` 返回首键；固定 Jayway 分别输出 `{id=1}` 和 PathNotFoundException。
- 原因：Python 统一用 json.dumps 渲染 dict，并把 keys() 结果直接降级成 list，丢失 JsonSmart provider 的 LinkedHashMap/LinkedKeySet 类型边界。
- 方案：用固定 2.8.0 Java 运行时取得权威类型矩阵；增加 Map、JSONArray、LinkedKeySet 和精确数字的 Python 等价值，禁止 LinkedKeySet 后索引。
- 防复发：覆盖插入顺序、Integer/Long/BigInteger、Double/BigDecimal、Map/JSONArray 文本、数组 null 和 keys() 后索引。

## XPath getElements 丢失 JXNode 类型身份

- 现象：number/boolean XPath 结果被包装成文本 DOM 节点，元素结果还能直接调用 `.html()`；固定版返回 JXNode，必须通过 isNumber/value 或 asElement 访问。
- 原因：JS bridge 为复用 Jsoup Elements API，把所有 getElements 结果都送入 `__elementList`。
- 方案：Python 回调输出 JXNode 类型标记，QuickJS 构造完整 JXNode API；只有 Jsoup 结果继续使用 Elements 包装。
- 防复发：同一脚本断言 count、boolean 和 element 三类节点的 is/as/value/toString 与 asElement 边界。

## namespace 转换误伤属性正则且共享 Elements 泄漏方法键

- 现象：初版 `prefix|tag` 转换会把 `[property~=category|status]` 中的正则改成 namespace；共享 DOM Elements 又让 `for…in` 枚举出 text/html/remove 等方法。
- 原因：namespace 使用了不区分方括号上下文的宽泛正则；QuickJS 对对象直接赋值的方法默认可枚举，而 Rhino 的 Java 类方法不属于记录键。
- 方案：namespace 只在字符串开头或 CSS 组合符后转换，单独处理 `*|tag`；Elements 方法及 length 用不可枚举属性定义。
- 防复发：同一组回归同时覆盖固定/通配 namespace、含 `|` 的属性正则，以及 `for…in` 只产生 `0,1`。

## concurrentRate 按通用限流含义修正了官方历史 bug

- 现象：Python 对 `2/40` 在第三次启动时等待；固定版前三次都能启动，第四次才进入等待。
- 原因：此前按注释“次数/毫秒”实现为严格 N 次，没有保留源码 `frequency` 初始为 1 且判断条件为 `> N` 的 off-by-one。
- 方案：窗口容量使用 N+1，同时仍按 source key 跨 ReaderEngine 实例共享预留记录。
- 防复发：并发发起四次，断言前三次处于同一窗口且第四次至少等待一个窗口。

## Python 额外接受固定版会拒绝的无 scheme 代理

- 现象：`proxy.example:8080` 在 Python 中被自动改成 HTTP 代理，固定 `getProxyClient` 因正则无匹配而失败。
- 原因：使用了常见客户端的宽松代理规范化，没有遵守历史源码限定的 scheme 和认证位置。
- 方案：独立实现固定 grammar；认证输入 `host:port@user@pass` 只在交给 aiohttp 时改排为标准 user-info URL。
- 防复发：覆盖普通、认证、SOCKS 和无 scheme 四类输入，非法形式必须抛错。

## 把 makeUpRule 的 `$0` 当成完整匹配并误伤 replacement

- 现象：Regex 记录规则 `$0-$1` 在 Python 输出 `whole-first`，固定版输出字面量 `$0-first`；初次修正后又把 `##...##$1` 的 replacement 当成记录插值。
- 原因：Python 直接对整条规则做统一捕获替换；固定 SourceRule 只在首个 `##` 前查找 `$\d{1,2}`，且 makeUpRule 仅在索引大于 0 时访问 List。
- 方案：先按首个 `##` 分层，只对规则主体替换 `$1..$99`；`$0`、非 List 结果和 replacement 均保持原文本进入各自后续阶段。
- 防复发：覆盖 `$0/$1/越界`、tuple 非 List、属性提取 replacement 和三井号首匹配替换。

## 用固定操作符优先级替代 RuleAnalyzer 的首操作符定型

- 现象：`i||em&&b` 被 Python 先算 `&&` 后得到额外 b；固定版先遇到 `||`，i 成功后立即短路。Python 还错误保护 Regex 括号里的 `&&`。
- 原因：通用 split_balanced 加了一套自定义优先级和统一转义规则，没有复现 RuleAnalyzer.elementsType、code/rule 双平衡器及 AnalyzeByRegex 的普通 splitNotBlank。
- 方案：扫描平衡组外第一个操作符作为本层类型，递归处理子层；区分两种反斜杠语义，并为 Regex 链单独使用非平衡切分。
- 防复发：覆盖首 `||` 短路、混合 `&&`、JSONPath 转义引号、Jsoup 不平衡异常、lazy 非法 fallback 与 Regex 括号内 `&&`。

## 静态审计选择器简化器进入运行时并二次截断 `@`

- 现象：平衡器正确保留 `div[data-key='a@b']` 后，运行时仍把它截成 `div[data-key='a`，导致合法属性选择器失败。
- 原因：`_jsoup_part` 调用了 `test_book_sources_async.simplify_legado_selector`；该函数为静态语料宽松识别而设计，会无条件删除首个 `@` 后内容，不属于固定 AnalyzeByJSoup。
- 方案：运行时只保留明确的 class/tag/id/text 旧语法转换，其余选择器原样交给 Jsoup 兼容层。
- 防复发：使用含 `@` 的属性值执行多段 `@span@text` 链并断言返回正文。

## JS 输出内容触发 Python 动态更换 SourceRule mode

- 现象：HTML 上 `<js>({foo:'bar'})</js>foo` 被 Python 当 JSON 读取出 bar；JSON 上 JS 返回 HTML 后 `a@href` 又自动切到 Jsoup。固定版两者都不会换 mode。
- 原因：Python 每个 JS 阶段后用 json.loads/HTML 外观重新推断 kind，绕过了 splitSourceRule 在执行前确定的 mode 与 AnalyzeRule.isJSON 状态。
- 方案：依据剩余 PythonSourceRule 的编译 mode 构造下一阶段输入；Default/XPath 使用 Rhino toString，Json 保留对象或严格解析字符串，Js 连续阶段直接传对象。
- 防复发：覆盖 HTML→NativeObject→Default、显式 Json、连续 Js、selector→Js→Default，以及 JSON→HTML→隐式 Json 异常。

## 列表流水线仍在每个 JS 阶段后重猜 JSON/HTML

- 现象：字段执行已固定 mode 后，搜索 bookList 和阅读 chapterList 仍会把 HTML 上 JS 返回的对象自动当 JSON，或把 JSON 上 JS 返回的 HTML 自动切到 Jsoup。
- 原因：两个列表循环各自维护 text/content_type，并在每次 JS 后根据 `{`、`[` 或 Python 对象类型重设 content_type，未复用 SourceRule 编译状态。
- 方案：分别保存初始 analyzer kind、当前 JS 对象和待执行 root；只有显式/编译 Json 才构建 JSON root，连续 Js 直接传对象，Default/XPath 使用 Rhino 字符串化。
- 防复发：搜索与阅读两套相同模式矩阵，加上原有 selector→Js、src、Elements、详情 init 与目录流水线回归。

## java.getString 的 NativeObject 被当成普通 JSON

- 现象：`java.getString('@Json:$.foo', {foo:'bar'})` 在 Python 返回 bar，固定版返回空；`foo<js>...` 在固定版只返回 bar，后续 JS 不执行。
- 原因：桥接层把 QuickJS Object 转为 dict 后统一走 JSONPath，没有实现 AnalyzeRule.getString/getStringList 开头的 NativeObject 专用分支。
- 方案：识别显式 content 的 JS Object，编译规则后只处理首 SourceRule，以完成后的 rule 为直接键并应用其 replaceRegex；列表结果按换行拆分。
- 防复发：同一脚本断言普通键、显式 Json 键不存在、后续 JS 忽略，以及 getStringList 首阶段行为。

## NativeObject makeUpRule 没有区分单参数键和多参数直返

- 现象：`@get:{key}` 应把变量值作为对象键，而 `prefix@get:{key}` 应直接返回拼接文本；`{{result.foo}}` 单参数仍查键，带前缀时才直返。Python此前完全未执行这些参数。
- 原因：NativeObject 快速路径只读取编译后的静态 rule，没有迁移 SourceRule.ruleParam/ruleType 与 getParamSize 分支。
- 方案：按固定 evalPattern 分解字面量、@get、嵌套规则和 JS；计算参数数目，JS 以 NativeObject result 在非重入运行实例求值，最后拆分 replaceRegex。
- 防复发：覆盖单/多 @get、普通/显式 Json、后续 JS 忽略、单/多 `{{JS}}`、整数格式及完成规则正则替换。

## 差异文档仍把规则缓存描述为部分路径缓存

- 现象：文档持续列出 SourceRule 缓存缺失，但当前编译器已缓存完整阶段程序；真正需要验证的是上下文状态是否进入缓存键。
- 原因：差异条目形成于 PythonRuleProgram 引入之前，后续实现完成后未以缓存身份和模式隔离夹具重新审计。
- 方案：保持不可变程序 LRU，并显式验证 allInOne/isJSON/isRegex 参与函数缓存键；无需模拟固定版可变对象的内部结构。
- 防复发：断言相同规则/状态对象身份复用，不同状态分别编译为 Default、Json、Regex 且对象不共享。

## ReadingEngine 外层把所有解析异常统一变成空值

- 现象：非法 Jsoup/XPath 选择器在 Python 的字段、列表和下一页规则中静默返回空；固定 AnalyzeRule 外层没有该 runCatching，选择器编译错误会传播。
- 原因：桌面兼容早期为尽量读出内容，在 `_strict_value/_list_nodes/_next_page_values` 加了宽泛 `except Exception`。
- 方案：删除执行器外层捕获，让各解析器只保留历史源码自身的异常处理边界。
- 防复发：分别对字段和列表传入不平衡属性选择器并断言异常，而合法无匹配仍返回普通空结果。

## 搜索对必填和可选字段使用了同一吞错策略

- 现象：书名、作者或详情 URL 的脚本/选择器失败被 Python 变成空字段；固定 BookList 对这些字段不 catch，但会单独 catch 简介、封面等可选字段。
- 原因：`_book_from_node.field` 为所有字段统一捕获 UnsupportedRule/RuleParseError/JsBridgeError，且 select_nodes/extract_value 还有更外层吞错。
- 方案：移除解析辅助层捕获；字段 helper 增加显式 tolerate，仅对固定源码 try/catch 覆盖的可选字段启用。
- 防复发：合法无匹配、非法 list selector、必填 name JS 失败和可选 cover JS 失败四类夹具同时存在。

## URL JS 被拆成多个位置特例执行

- 现象：Python 分别处理前置 `<js>`、整条 `@js:`、尾置 `@js:` 和中间 `<js>`，无法可靠复现多个普通/JS 片段逐段共享 result；纯前置 JS 也没有拿到固定版的完整原规则初值。
- 原因：URL 路径早于统一 SourceRule 编译器建立，后续只叠加了位置判断，没有迁移 `AnalyzeUrl.analyzeJs` 的单循环语义。
- 方案：使用 `compile_rule_program` 的原始阶段串行执行；普通阶段替换 `@result`，JS 阶段以当前 result 建立 JsContext，完成后统一进入 URL 模板和页码替换。
- 防复发：用两个 `<js>` 和夹在中间的普通 `@result` 片段断言每一阶段的输入与输出顺序。

## SOCKS URL 被当作 aiohttp HTTP proxy 参数

- 现象：代理字符串能够通过 grammar 测试，但 SOCKS4/SOCKS5 实际请求交给 aiohttp `proxy=`，该参数只实现 HTTP 代理协议，无法完成 SOCKS 握手。
- 原因：此前只对齐了代理字符串解析，未区分代理协议对应的传输层。
- 方案：引入 aiohttp-socks；SOCKS 代理创建 session connector，HTTP 代理保留 request proxy，二者互斥。
- 防复发：模拟认证 SOCKS5 请求，断言标准化 URL 传给 ProxyConnector、session 使用该 connector，request 参数中不再出现 proxy。

## 裸毫秒 concurrentRate 只限制开始时间

- 现象：首个请求执行时间超过并发间隔时，Python 允许第二个请求按预约时间启动；固定版 frequency 在 fetchEnd 前始终大于零，第二个请求必须继续等待。
- 原因：旧实现用全局 start reservation 近似两种 concurrentRate，没有建模非并发模式的请求占用计数。
- 方案：真实 `_request` 使用 acquire/finally-release；`N/T` 保持窗口计数，裸毫秒模式维护 active、首次开始时间并循环复检。
- 防复发：让首个模拟响应阻塞超过一个间隔，断言第二个 session request 直到首个响应释放后才出现。

## UnicodeDammit 与固定 ICU4J 返回不同编码

- 现象：无 meta/header 的 GB18030 或歧义东亚字节由 UnicodeDammit 返回 GB2312/Big5，而固定 detector 返回 GB18030/KOI8-R；部分内容最终解码结果会不同。
- 原因：BeautifulSoup 使用的探测器与 Legado 内嵌 ICU4J 识别器及置信度排序不是同一算法。
- 方案：编译固定 detector 为开发 oracle；运行时用 Python ctypes 调 ICU CharsetDetector C API，保留降级路径。继续以 oracle 定位 ICU 版本模型差异并迁移固定模型。
- 防复发：固定中文 GB18030 与故意歧义的日文 Big5 字节均断言 detector 名称，不只断言可解码。

## Python 默认请求头与固定 HttpHelper 不同

- 现象：Python 使用 Android Chrome 120 UA，且缺少固定拦截器每次追加的 Keep-Alive、Connection、Cache-Control；字符串 UA `null` 还会被原样发出。
- 原因：网络实现只合并了 engine/source/request 三层 dict，没有迁移 HttpHelper application interceptor。
- 方案：使用固定 Chrome 119 Windows UA；合并后处理 null sentinel，再以可重复 MultiDict 追加三个拦截器 header。
- 防复发：断言默认 UA 全文本、null 删除，以及自定义和固定 Cache-Control 两个值的顺序。

## aiohttp 自动解压范围大于 OkHttp

- 现象：aiohttp 默认自动解压 gzip、deflate、br，即使书源显式设置 Accept-Encoding；固定 OkHttp 仅在自己注入 gzip 时透明解压，并同步删除两个响应头。
- 原因：ClientSession 的 auto_decompress 与 OkHttp BridgeInterceptor 的 transparentGzip 条件不同。
- 方案：关闭 aiohttp 自动解压，Python 显式判断 Accept-Encoding/Range，注入 gzip 后手工解压并调整 last_response 头；其他编码保持原始字节。
- 防复发：同一 gzip 响应分别使用默认请求和显式 Accept-Encoding，断言 hex body、bodyBytes 与响应头相反分支。

## 重定向方法和敏感头缺少固定矩阵证据

- 现象：此前依赖 aiohttp 默认行为，但没有证明与 OkHttp 对 POST 302/307 及跨 origin Authorization 的处理一致。
- 原因：网络差异文档只记录“未做字节级差分”，缺少可重复的本地双 origin 测试。
- 方案：启动两个临时 aiohttp 服务，记录最终 method/body/header，并通过真实 ReaderEngine 请求链验证。
- 防复发：302、307、跨端口 origin 三条断言固定存在，不依赖外网。

## 系统 ICU 与固定内嵌 ICU4J 的候选集合和评分不同

- 现象：ICU 78 会把无 BOM UTF-16、GB18030 或单字节歧义内容选为 IBM420、错误端序 UTF-16 或新版单字节模型；固定 oracle 的最终正文不同。
- 原因：固定源码禁用四个 IBM recognizer，且 Unicode、Big5、希腊语言模型与系统 ICU 版本的置信度及同分顺序不同。
- 方案：Python 对 detectAll 候选过滤 IBM；覆盖固定 Unicode 评分/顺序、Big5 common-character 与希腊 n-gram 分数，再与其余 ICU 候选统一按固定注册顺序选最大值。
- 防复发：保留韩国文本 GB18030、希腊文本 GB18030、无 BOM UTF-16、Latin 歧义端序及 Big5/KOI8-R 固定夹具，并以开发 oracle 跑 284 组合矩阵。

## html.parser 没有执行 Jsoup 的 HTML5 树修复

- 现象：缺失 tbody，未自动闭合 p/li/td，head 吞入 body；孤立 td/tr 还被 Python 额外保留成元素，导致 CSS/XPath 节点数与层级不同。
- 原因：BeautifulSoup 内置 html.parser 的纠错算法不是 Jsoup 使用的 HTML5 tree builder。
- 方案：增加固定 Jsoup oracle；主 HTML DOM 切换 html5lib，并让 Python 与 JS 规则入口共享该解析函数。

## SoupSieve 与 Jsoup 的 selector 转义语义不同

- 现象：SoupSieve 会把 `\\3A` 当 CSS code point、解码未引号属性值中的反斜线；Jsoup 1.16.2 将前者按数字文本匹配，后者不产生匹配，并接受属性值里的字面冒号和空格。
- 原因：两套 selector parser 的 escape token 和容错 grammar 不同。
- 方案：选择前按固定 Jsoup oracle 归一化十六进制样式转义与重复逗号组，只对未引号属性值补引号；反斜线值保持 Jsoup 的无匹配结果。
- 防复发：覆盖 `#a\\:b`、`#a\\3A b`、`.x\\+y`、`.\\31 23`、重复逗号，以及含空格、冒号、反斜线的属性值。

## BeautifulSoup 字符串化不等于 Jsoup outerHtml

- 现象：属性会被重排，块节点没有 Jsoup 缩进，NBSP、自闭合和 XML CDATA/PI 输出不同；HTML 未知自闭合标签还可能吞掉后续兄弟。
- 原因：此前 `_jsoup_html_markup` 只在 BeautifulSoup 输出后修补 void 和布尔属性，没有执行固定 `Node` visitor 与 `OutputSettings`。
- 方案：迁移固定 Jsoup 的 Tag 分类、缩进、文本规范化、属性折叠和 HTML/XML 分支；解析前把未知 `<x/>` 展开以阻止 html5lib 吞兄弟，同时在 DOM 上保留自闭合状态。
- 防复发：开发 oracle 批量比较 HTML/XML 的 outerHtml/html，并以 38 个固定结果零差异作为门禁。

## 畸形 XML 错误回退为 HTML DOM

- 现象：错配或未闭合 XML 会被小写化、插入 HTML 缩进并把 PI 变成注释，结构也按 HTML adoption rules 改写。
- 原因：严格 minidom 失败后旧实现直接使用 html5lib，而固定 Jsoup 使用独立、宽容且大小写敏感的 `XmlTreeBuilder`。
- 方案：迁移 start/end/character/comment/CDATA/PI 的栈式处理；结束标签只在最近 256 层内寻找并弹栈，找不到则忽略，EOF 保留并由序列化器闭合。
- 防复发：5 组畸形 XML 自动化子用例及固定 oracle 的 outerHtml/html 双结果比较。
- 防复发：table/tbody/td、p+div、重复 li、孤立 td/tr 同时覆盖 CSS 和 XPath 路径。

## 通配 namespace 只能作为完整 selector

- 现象：`*|content` 单独使用可工作，但 `div > *|span` 被 SoupSieve 当成不支持的 namespace 语法。
- 原因：旧兼容逻辑只对整条规则做 fullmatch 后手工筛选。
- 方案：扫描当前 DOM 的 literal colon tag 名，把复合 wildcard namespace 展开为 `:is(local, prefix\\:local...)`，再交给 SoupSieve 处理组合关系。
- 防复发：父元素下普通 span、带前缀 span、嵌套带前缀 span 的 oracle 矩阵只选直接两个节点。

## 属性正则被 CSS 十六进制转义预处理破坏

- 现象：`[data-num~=\d+]` 中的 `\d` 被识别成 CSS 十六进制转义并变成 `d`；字符类或转义 `]` 又会被简单正则过早截断。
- 原因：属性正则提取晚于 CSS identifier 预处理，并使用 `[^]]+`，与固定 QueryParser 的 `chompBalanced('[', ']')` 不同。
- 方案：先平衡扫描并抽出 Java 属性正则，再处理普通 CSS；保留反斜线与嵌套字符类，不平衡时传播语法错误。
- 防复发：固定 oracle 与 Python 测试同时覆盖 `\d+`、`[A-Z]`、`A\]B`、`[^\]]+`、空/不平衡正则和负数 `:eq`。

## 用 BigInt 代替 Rhino primitive Long 造成额外精度

- 现象：Python 桥的 `Long.parseLong(MAX).toString()` 返回精确的 9223372036854775807；固定 Rhino 把 Java primitive long 转成 JS Number，实际返回 9223372036854776000。与此同时 boxed Long 的 toString 又必须保持精确值。
- 原因：旧实现让 parseLong 和 valueOf 都直接返回 QuickJS BigInt，没有区分 Java primitive 与 NativeJavaObject boxed 对象。
- 方案：boxed 内部用不可枚举 BigInt 保存精确值，valueOf/toString 分别执行 Rhino 数值强制与 Java 文本；parse/xxxValue 返回 Number。其余 primitive wrapper 使用相同对象模型和 Java 范围检查。
- 防复发：固定 Rhino oracle 同时断言 typeof、宽松/严格相等、instanceof、MAX_VALUE、parse/valueOf、getClass/TYPE 及 JavaException.javaException。

## Python Unicode 空白和 double 舍入改变 BookHelp 格式

- 现象：全角空格被书名格式化额外删除，15500 被显示成 1.6万字；搜索结果还缺少分类、字数、最新章节和来源字段。
- 原因：Python `\s/strip` 默认 Unicode，而固定 Java Regex 的 `\s` 与 `trim { it <= ' ' }` 是 ASCII 边界；字数直接用 Python double，没有经过 Kotlin 历史 Float 表达式。
- 方案：显式 ASCII 空白字符类与 trim，字数在 DecimalFormat 前量化为 float32；搜索和详情字段按 BookList/BookInfo 源码顺序格式化与赋值。
- 防复发：Java oracle 覆盖全角空格、作者前后缀、10000 阈值、12500/15500 舍入、Int 边界和非数字原样返回；集成测试同时断言搜索与详情元数据。

## 正文在整章 join 后才格式化 HTML

- 现象：跨页 replaceRegex 能看到固定版已经移除的 HTML 标签；图片相对地址没有按各页 redirectUrl 解析，`&lt;b&gt;` 最终又被 BeautifulSoup 当成真实标签删除。
- 原因：旧流程把原始页内容直接 join，最后依赖 UI 块解析统一清理，颠倒了 BookContent.analyzeContent 的逐页 HtmlFormatter 与最终反转义顺序。
- 方案：每页提取后立即 formatKeepImg 和 HTML4 反转义，再 join/整章替换；块解析只拆 formatter 保留的规范 img，其余尖括号按正文文本保存。
- 防复发：同时覆盖相对 data-src、带请求参数的 src、跨页替换顺序与转义标签文字。

## JSON 快照无法复现 SharedJsScope 闭包

- 现象：`const next=counter()` 在连续两次规则调用中都返回 1；固定 Rhino 返回 1、2。对象身份、函数属性和不可枚举状态也会随新建 QuickJS Context 丢失。
- 原因：旧实现只把 jsLib 顶层可 JSON 化变量写入字典，下一次重新执行 jsLib 后赋值；闭包捕获的词法环境无法序列化。
- 方案：按 jsLib MD5 持久保存真实 QuickJS Context，只初始化库一次；规则放入新的 IIFE direct eval，模拟 BaseSource 新 runtime scope 以共享库 scope 为 prototype。
- 防复发：同时断言闭包连续递增及同一规则中的 `let` 可跨两次求值重新声明，并运行完整兼容与 1,066 书源静态审计门禁。

## 只有 SearchModel 合并函数，没有搜索生命周期

- 现象：单源解析结果可合并，但换关键词不会取消旧任务，同一搜索无法按官方方式翻页，也没有 Room 写入产生的后续换源数据。
- 原因：旧实现只迁移 `mergeItems` 算法，没有移植 SearchModel 的状态机、固定线程池/超时和 searchBookDao 副作用。
- 方案：以 generation 隔离并取消旧任务，使用至多 9 个 asyncio worker 顺序领取书源；每源结果先写 SQLite REPLACE，再合并并通知调用方。
- 防复发：测试同时制造受控并发、连续页码和未完成旧搜索，断言峰值、取消传播、回调顺序及数据库读取结果。

## 详情 init 错把 Elements 截成第一个节点

- 现象：`init: section` 只保留首个 section，后续字段无法从其余节点提取；JS 返回 null 又静默退回原页面。
- 原因：旧 `_initialize_detail` 复用了列表入口并执行 `nodes[0]`，没有复现 AnalyzeRule.getElement 返回对象再 setContent 的类型与非空约束。
- 方案：列表流水线增加 getElement 保留模式；Jsoup Elements 作为多上下文执行选择器，JSON/JS 原值保留，null 直接断言。详情同时区分原始 body 和 init 后 content。
- 防复发：覆盖多节点 init、JS/JSON 串联、null、缓存 HTML 零网络、web file 空下载链接和 BookType 位值。

## 正文服务混合了官方原始结果和桌面展示结果

- 现象：`content()` 丢失 img 标记，只返回文本块；还会无规则依据地删除“本章未完”提示。规则为空时反而请求页面并抛空正文，首章 nextChapter 回退会把当前 URL 当成边界直接跳过。
- 原因：旧接口从 UI 的 `plain_text` 反推规则结果，且缓存/导航逻辑主要散落在 ReadingView，没有按 WebBook/BookContent/ContentProcessor 三层分离。
- 方案：ChapterContent 增加 raw_content；BookContent 原始字符串和 UI 块各自保存。短路、下一章回退、标题更新和 needSave 图片/正文持久化全部下沉到引擎。
- 防复发：覆盖 img 原样返回、提示语保留、零规则/合成卷零网络、needSave 真值、目录标题写回及首章回退。

## 登录按钮错误提前保存到 infoMap

- 现象：点击任意 loginUi 按钮都会写通用 infoMap，且 action 从 infoMap 读取字段；固定版按钮不持久化，字段只作为 result Map。登录对话框再次打开也读错存储。
- 原因：旧 Python API 把“按钮 action”和“确认登录”合成一个方法，没有迁移 SourceLoginDialog 的两条生命周期。
- 方案：execute_login_action 只执行 loginJs+action 并注入 result；submit_login 专门保存 source loginInfo 后调用 login()。schema 从 source.getLoginInfoMap 回放。
- 防复发：按钮夹具使用 result.Account，提交夹具断言 login() 执行时已经能读到持久字段及写入的登录 header。

## 用现代字体库展开轮廓反而偏离固定 QueryTTF

- 现象：Python 会解析复合字形和 CFF，并以绝对坐标/端点形成签名；固定版只读取简单 glyf 的相对坐标增量，换字体反查可能得到不同字符。
- 原因：此前把“支持更多字体”误当成兼容，而没有逐行核对 QueryTTF.java 的 cmap 选择顺序、复合字形跳过和 glyph 列表索引特性。
- 方案：改用纯 Python 二进制解析器严格移植固定格式 0/4/6/12 与简单 glyf 流程；replaceFont 只使用固定版 codeToGlyph/glyphToCode 和 limit 范围。
- 防复发：保留由 FontBuilder 生成的真实 TTF 夹具，并把 QueryTTF 固定源码作为实现注释与差异验收依据。

## 推测 FormElement 支持外部 form=id 导致过度实现

- 现象：初版 Python 长尾把表单外的 `form=id` 控件加入 elements/formData，并提交无 type 的 button；实际 Jsoup 1.16.2 oracle 分别给出 6 个控件和 `[r=R, file=F, c=on, s=one]`。
- 原因：按浏览器标准推断行为，没有先执行固定依赖版本。
- 方案：直接编译运行 `JsoupLongTailOracle.java`，按 HtmlTreeBuilder 的实际关联集合和 Tag.isFormSubmittable 结果修正。
- 防复发：NodeFilter 生命周期与 FormElement 长尾同时保留 Java oracle 输出和 Python 精确断言，避免再次用现代标准替代历史行为。
