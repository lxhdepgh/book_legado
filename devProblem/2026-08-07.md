# 2026-08-07 已解决问题

## QuickJS 批量检测导致 Windows 进程异常退出

- 现象：批量书源检测时触发 `runtime_data->thread_state` 原生断言，进程以 `0xC0000409` 退出。
- 原因：Windows 下 CPython QuickJS 扩展对线程与回调生命周期敏感；协程超时不能可靠中止已进入原生扩展的任务。
- 方案：QuickJS 执行固定到单一专用线程；批量检测跳过高风险原生 JS 并标记为需要在阅读页单独验证；普通网络、搜索与分类检测保持并发。
- 防复发：保留并发线程归属测试和真实 JS 书源批量安全检测。

## 性能回归风险

- 问题：书源导入、管理页搜索和规则规范化属于高频路径，重复计算会随书源数量增长。
- 方案：复用 dataclass 字段映射；缓存 URL、搜索文本和规则规范化结果；搜索输入增加 180ms 防抖；避免搜索时重建未变化的分组选项。
- 正确性：缓存键包含所有可变输入，字段修改后不会返回旧值；LRU 缓存均设置容量上限。

## 语料数量测试前置条件失效

- 现象：完整测试中一项固定断言 `resource/bookSource.json` 必须有 1127 条，当前文件实际为 1066 条。
- 处理：不修改用户书源数据，也不放宽语料完整性断言；其余测试独立执行验证。

## 阅读路径需要重复操作

- 现象：从书架打开书籍后仍停留在目录，需要重新寻找上次章节；章节导航只位于正文底部；误触删除会立即移出书架。
- 方案：复用已持久化的阅读位置自动续读；增加固定在正文顶部的导航与字号工具栏；删除前增加确认步骤。
- 防复发：续读匹配与字号边界由独立测试覆盖，书架仍使用原有持久化格式，兼容已有阅读记录。

## 分类第一页 URL 丢失数字零

- 现象：使用 `{{page - 1}}`、`{{(page-1)*20}}` 等表达式的分类标签，第一页请求被渲染成 `page=` 或 `offset=`，部分服务器返回 HTTP 400。
- 原因：内联 URL 模板使用 `str(result or "")` 写回 JavaScript 结果，数字 `0` 被 Python 当作假值转换为空字符串。
- 方案：仅在内联模板写回阶段识别非布尔数值零并输出 `"0"`；`None`、`False`、空字符串和空容器继续保持原行为，避免扩大兼容性变化。
- 影响范围：当前语料中发现 36 个书源使用第一页可能产生零的分类表达式。
- 防复发：新增第一页零值、第二页正值和布尔假值兼容测试。

## 应用重启后无法恢复准确阅读点

- 现象：原实现只保存章节 URL 和索引，不保存章内位置；目录与正文缓存仅存在于内存，书架每次打开都重新请求目录。
- 原因：阅读状态模型缺少滚动信息，且自动连续拼接多章使单一像素偏移无法在重启后还原。
- 方案：以单章作为定位单位，持久化滚动偏移、比例、字号和时间；目录与正文写入独立磁盘缓存，书架优先走缓存直接续读。
- 兼容性：沿用 `bookshelf.json` 的 `reading` 对象并只增加字段，旧记录仍可按章节 URL/索引恢复；缺少缓存时自动回退网络加载。
- 防复发：覆盖缓存重开、目录免网络打开、阅读状态重开、目录筛选和正倒序测试。

## 书架数据与 Legado 阅读模型不一致

- 现象：原书架只保存收藏元数据，阅读进度位于项目自定义的嵌套对象中，无法直接复用 Legado 的书籍进度语义。
- 原因：缺少 Legado `Book` 实体中的当前章节、章内字符位置、最近阅读时间和目录总数等字段。
- 方案：在不破坏旧 JSON 的前提下增加 Legado 字段，并让章节打开、滚动和目录加载同时更新两套兼容表示；加载旧书架时自动迁移。
- 防复发：持久化测试同时断言旧 `reading` 字段和 Legado `durChapter*` 字段。

## 视频正文调用 `startBrowser` 后出现 Python call failed

- 现象：视频章节目录可以加载，但打开章节后提示 `InternalError: Python call failed`，规则位置为 `startBrowser(<input>)`。
- 原因：规则桥接错误地让 `startBrowser()` 与 `startBrowserAwait()` 共用阻塞网页抓取回调。前者本应触发打开后立即返回，却在正文解析期间反向等待 Python UI，导致调用失败。
- 方案：拆分接口语义；`startBrowser()` 返回包含目标 URL 的响应对象且不阻塞解析，`startBrowserAwait()` 保持登录/验证等待行为。播放器请求合并书源请求头。
- 防复发：加入截图对应规则的完整离线测试，断言浏览器抓取回调未被调用，并断言返回的 `.m3u8` 直链被识别为视频内容。

## 连续点击书架时旧目录覆盖新书

- 现象：目录异步加载较慢时，点击第二本书后，第一本书较晚返回的目录会覆盖当前界面。
- 原因：所有书架打开请求共享界面状态，没有请求身份和失效判断；点击新书也没有取消旧任务。
- 方案：为每次点击分配递增的打开会话编号，取消上一任务，并在缓存、网络目录和正文返回后校验会话；旧会话只允许结束，不允许回写 UI。
- 交互分流：有进度直接进入阅读恢复，无进度先显示详情再加载目录。
- 防复发：新增过期会话测试，确保它在目录加载前终止且不会替换当前书籍。

## 第一本书恢复后切换其他书不再恢复

- 现象：首次从书架续读正常；返回书架打开第二本有进度的书时，正文可能不恢复或进度被污染。
- 原因：切书时先替换 `_current_book`，随后旧章节仍会保存滚动进度，导致旧章节写入新书；共享规则变量、预取缓存和当前章节也未完全重置。
- 方案：切书前先持久化旧书，再统一重置阅读会话，包括章节、目录、滚动、加载锁、预取、规则变量及引擎当前书籍，然后启动新会话。
- 防复发：新增两本已缓存书籍连续恢复测试，分别断言两次恢复命中各自章节；保留过期会话不得回写测试。

## 书架只有阅读入口，缺少 Legado 管理层

- 问题：书架无法搜索、筛选、分组、切换布局、批量更新或查看未读和更新错误。
- 方案：重构书架顶部工具栏和书项层级，增加搜索、特殊/自定义分组、五种排序、列表/网格、批量刷新与单书管理；刷新任务采用独立引擎。
- 数据：补齐 `latestChapterTime`、`lastCheckCount`、`updateError`、`groupName` 等持久字段，并兼容旧 JSON 自动迁移。
- 防复发：增加书架刷新结果和自定义分组重启持久化测试。

## 新书无缓存时目录和阅读页仍显示旧书

- 现象：点击无本地缓存的新书后，在其网络目录返回前，目录或阅读层级继续显示上一本文字和状态，容易误认为加载了旧书。
- 排查：实际 `bookshelf.json` 中两本书的 `bookUrl`、`tocUrl`、章节 URL 均不同，排除缓存摘要碰撞和书架身份映射错误。
- 原因：原切书重置只清理内部数据，没有同步清空目录与正文控件；旧状态因此留在屏幕上。
- 方案：将内部状态和可见控件作为一个切书事务共同重置，并在正文任务入口校验打开会话。
- 防复发：测试先注入旧书目录、正文和导航状态，再切换无缓存新书，断言所有旧信息消失且占位文案属于新书。

## 目录作为顶层 Tab 不符合移动端阅读层级

- 问题：书架、目录和阅读并列时，目录与书籍详情割裂，用户可能在没有明确书籍上下文的情况下切换目录；启动还默认进入书源管理。
- 方案：改为书架到详情章节再到阅读的层级导航。目录属于当前书籍详情，正文只通过“章节”返回详情页；应用默认进入阅读书架。
- APK 考量：保留 Material 组件和响应式布局，不引入桌面专属导航控件；桌面 Edge 验证仍只在 Windows 分支使用。
- 防复发：测试断言详情页同时包含目录工具栏和章节列表、阅读返回目标为详情页，并断言应用默认导航索引为阅读。

## 合并详情目录后丢失自动续读

- 现象：点击已有进度书籍只停留在详情目录页，不再恢复原阅读位置；正文也缺少直接回书架入口。
- 原因：重构时为了阻止目录加载自动跳正文，统一移除了传入 `_run_chapters` 的恢复记录，没有区分有进度和无进度书籍。
- 方案：有进度时继续传入恢复记录，目录准备后自动加载保存章节；无进度仍不自动进入正文。正文顶部和末尾分别提供回书架、回章节入口。
- 防复发：保留连续两本缓存书自动恢复测试，并断言正文导航同时包含书架与章节控件。
