## 1. 问题与根因

找书页打开书源后，「分类」不出现（或只有一条「默认」），点进去书单为空。

根因链（三层，已逐层证实）：

1. **FFI 层是桩**。`doBrowseCategories`（[engine.go:1320](../../legodo_dart/backend_go/pkg/ffi/engine.go#L1320)）忽略 `exploreUrl`，硬编码返回 `[{"title":"默认","url":""}]`；`doBrowseBooks`（[engine.go:1340](../../legodo_dart/backend_go/pkg/ffi/engine.go#L1340)）只做 `{{page}}` 字符串替换，且**出错时 log 后静默回空列表**——UI 因此显示「0 本」而不是报错。
2. **引擎层是简化版**。`RuleEngine.BrowseBooks`（[rule_engine.go:609](../../legodo_dart/backend_go/internal/engine/rule_engine.go#L609)）只做「CSS 选择器 bookList + 逐字段 `node.Field`」，缺：ruleSearch 继承、`{{...}}` JS 模板渲染、`@js:` 分类 URL、`<a,b>` 页对、请求选项、`&&/||` 联合、`@json`/`@js` bookList、`$.` 字段、`##` 后缀、字段级 JS、单容器批取、详情页单书回落、去重。
3. **JS 运行时没有 Java 面**。`pkg/jsruntime`（111 行）只注入 `java.baseUrl`/`baseUrl`/`page`/`result=""`，无 `java.ajax`、无 `Packages.org.jsoup`、无 watchdog——真库 157 个 JS 分类脚本里 109 个用到 java 面（`java.ajax` 64 个）。

对照组：Python 参考实现在 `legodo_dart/app/services/engine/`（`resolve_explore_categories` / `explore()` / `explore_document()` / `legado_rule_parser.evaluate` / `legado_js.py` Java shim），语义齐全，本方案逐项对齐它。

## 4. 修复设计（分层，语义逐项对齐 Python）

**0 号原则：未覆盖的规则形状一律显式报错（书单级）或记日志回落空值（字段级），不许静默吞空。** 书单出错时 `browse_books` 返错误信封（UI 已有「分类书单加载失败：$error」文案可用），空结果才是「0 本」。

### L1 分类解析（接真实解析，替换 stub）

- `doBrowseCategories` 改调与 check 同一口：静态 JSON / `行式 ::` / `@js:` goja 求值 → 按 title∧url 过滤。
- 分类解析函数从 `check_service.go` 的私有实现提为共享（engine 或独立包），两链路同一实现。

### L2 分类 URL 解析（新 `ResolveCategoryRequest`）

对齐 Python `explore()` + `legado_url.parse_search_url`：

1. `{{...}}` 渲染：`{{page}}`/`{{key}}` 快路径 + 其余表达式走 goja（注入 source/page/key/result/baseUrl）。
2. `@js:` 分类 URL：求值；返回 dict → 当请求对象；返回字符串 → 按 URL 解析。
3. `<a,b>` 页对：第 1 页取前项，后续取后项（页超列表复用末项）。
4. `,{请求选项}`：宽松 JSON 解析（引号/单引号/无引号键），取 `method`/`body`/`headers`/`charset`；body 中 `{{page}}`/`{{key}}` 替换；`webView:true` → 明确报错（一期不做，见 §7）。
5. 相对地址按 `bookSourceUrl` 回拼 + 非 ASCII 编码（复用现件）。

### L3 抓取

- GET/POST 走 `httpclient`（method/body/headers/编码已具备）；沿用源级 cookie。
- 单次超时保持 15s（FFI 现状），脚本级 watchdog 单独管（见 L6）。

### L4 列表管线（对齐 `_list_rule_pipeline` + `select_nodes`）

- ruleSearch + ruleExplore **合并**（explore 非空字段覆盖 search）——231 源靠继承搜索规则才能出单。
- `-`/`+` 前缀（倒序/去重语义按 Python）。
- bookList 求值：单阶段 `@js:` → goja（注入 `result`=响应文本）；`@css:`/CSS/联合（`&&` 拼接、`||` 惰性回退、`%%` 交错）→ goja 后接选择器的多阶段循环亦移植；`@xpath:`/`/` 开头 → XPath；`@json:`/`$.`/`$..` → mini JSONPath（JSON 载荷或 JSON 嗅探）。
- 单容器批取（1 个容器命中且 names/urls 各 ≥2 → 按位置组书）。
- 空列表回落：无 `bookUrlPattern` 时把当页按详情页解析成单书；仍空则返空。

### L5 字段层

- 取值口升级（ruleparser.Field 扩展，search/toc 链路顺带受益）：
  - `##` 后缀 `regex##replacement`（含 Java 正则语义，用 regexp2；Python 侧同类实现 `_apply_regex_suffix`）。
  - `&&`/`||` 联合。
  - `$.`/`@json:` JSON 路径（gjson + mini 深搜）。
  - `@js:` 字段（已有 fieldRaw，补 source/page 上下文）。
- bookUrl/coverUrl 按当页 URL 回拼 `resolvePageURL`；`javascript:`/`void(` 置空。
- 去重（按 url，保首条）、name 必填过滤。

### L6 JS 沙箱扩展（jsruntime）

- Context 扩展：`Source`/`Key`/`Page`/`Result`/`Variables`/Ajax 回调。
- 注入面：`baseUrl`、`page`、`key`、`result`、`source`（对齐 Python bootstrap）；`java.ajax(url)`（同步 GET，5s 超时，带源 cookie/UA）；`java.toast/log/refreshExplore/t/longToast` 无操作桩；`java.base64Encode`；`java.get/put`（变量袋）；`Packages.org.jsoup.Jsoup.parse`（DOM 子集：`select/size/get/text/attr/html/outerHtml`，基于 ruleparser 适配；选择器先过 jsoup 兼容归一，如 `[href^=/book/]` 无引号属性值）。
- **Watchdog**：goja `vm.Interrupt` + 脚本级超时（默认 5s），防书源脚本死循环挂死 DLL 调用线程。
- 每次求值后清场复位（沿用现池化模式）。

### L7 接线与错误语义

- `doBrowseBooks`：去掉静默吞空；`ErrUnsupported`（如 webView）与网络/解析错误都返 `failResult(err)`。
- check 收敛：`checkCategoryPage` 不再预解析 `resolveExploreURL`，改把原始分类 URL + page 直传引擎（删掉 check 里的重复实现，避免双份漂移）；check 顺带获得 JS 分类/@js URL/POST 选项能力。
