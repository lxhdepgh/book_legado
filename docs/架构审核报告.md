## 1. 审核范围与方法

### 1.1 范围

本轮审核覆盖 Legado 桌面端重构（M1→M7 新树）的进程内多服务架构全链路：

| 域 | 对象 | 数量/形态 |
|---|---|---|
| 基础设施 | `EventBus` / `EngineHub`（守护 loop + EngineProxy）/ `ServiceHub`（Kahn 拓扑排序）/ `Service` 生命周期状态机 | 3 件核心件 |
| 服务层 | `app/services/**`（5 域 + 根级服务） | **31 个服务** |
| 视图层 | `app/controllers/**` | **18 个控制器** |
| 视图 | `app/views/**`（阅读/书源/工具/配置四棵视图树） | 18 个视图工厂 |
| 存储 | `StorageService` + SQLite **schema v6** + 迁移幂等链 | 主连接单实例 |
| 导入链 | 选文件/图片/URL → `OnlineImportService._dispatch` → `SourceService.import_sources_json` → `ImportFinishedEvent` → 渲染 | 端到端 |
| 导航 | `ViewRegistry.NAV_META`（20 目的地）+ `NavigationHost` 三组 NavigationRail | 3 组 20 目的地 |
| 打包面 | `LegadoReader.spec`（onedir windowed）+ expat 钉版 + 冒烟 | PyInstaller |

### 1.2 方法

1. **只读源码走查 + AST 探针**：未 import 业务模块、首遍未跑 pytest、未改源文件；探针交叉比对"声明 `dependencies` vs `on_start` 实际 `hub.require`"。
2. **Flet 0.86.5 实测探针**：`page.services` / `overlay`、`Dropdown.on_select`（无 `on_change`）、`FilePicker` 行为、`ElevatedButton` deprecation 等均在本机 flet 0.86.5 下逐一验证。
3. **修复后回归**：低风险修复与导航改版落地后，全量 pytest 回归至 `834 passed`。
4. **分类口径**：
   - **已确认问题（本轮已修）**：源码可定位、逻辑闭合、本轮已修复并有测试守护。
   - **已确认问题（未修）**：源码可定位，但需后续排期或产品拍板。
   - **需用户确认**：依赖运行期/三方行为（flet loop、sqlite 线程模型、真桌面弹窗）才能最终判定。
   - **设计取舍**：作者有意为之、有代价，本轮不动。

## 6. 导入链路专项结论

### 6.1 链路核查结论（代码侧修复全部在位并验证）

代码侧修复全部在位，并在 flet 0.86.5 实测下列 API 均存在：

- `page.services` 存在、`FilePicker` 是 `Service`、`pick_files` 支持 `with_data`、`FilePickerFile.path`/`bytes` 均在；
- `SourceImportController` 已 `with_data=True` + `bytes` 兜底；
- `NavigationHost.show` 把 `file_picker`/`image_picker` **append 到 `page.services`（绝不 overlay）**；
- 窗口标题已设。

端到端链路：

```
pick_file → OnlineImportService.import_from_file / _dispatch
         → SourceService.import_sources_json（SQLite book_sources 事务落库）
         → ImportFinishedEvent
         → _on_import_finished 渲染到结果区
```

`OnlineImportService._dispatch` 对 pending/未知/解析失败/落库异常**每条路径都 `_emit`**，errors+warnings 合并进 `ImportFinishedEvent.errors`，全链不丢异常。
