# 第一百零五轮 收：Go FFI 引擎编译修复 + 类型对齐（2026-10-15）

这一轮是 **Go 后端 FFI 层深度修复**：engine.go 中新增的 reader/browse/search handlers 存在大量类型不匹配、方法签名错误、重复声明等编译错误，导致 DLL 无法生成。通过系统性修正所有模型字段名和函数调用，最终编译出 39MB legodo_engine.dll。

## 1. 修复前状态

编译器报错列表（c-shared 模式下共 ~15 类错误）：

| # | 错误类型 | 示例 |
|---|---------|------|
| 1 | `b.URL undefined` — models.BookItem 无 URL 字段 | bookToMap / bookToMapFull 引用内部模型 |
| 2 | `ch.WordCount undefined` | Chapter 结构体缺少 WordCount |
| 3 | `doReaderOpen redeclared` | engine.go 中有新旧两份 doReaderOpen |
| 4 | `doSwitchScan redeclared` | engine.go 中有新旧两份 doSwitchScan |
| 5 | `*models.Chapter{} ≠ *internal/models.Chapter{}` | 类型混用 |
| 6 | `book.BookURL undefined` | internal 模型字段是 `URL` 而非 `BookURL` |
| 7 | `src.RuleExplore.SortList undefined` | ExploreRule 无此字段 |
| 8 | `svc.Add(book)` 类型不匹配 | BookshelfService.Add 接受 models.BookItem |
| 9 | `okResult(map{...})` 缺参数 | okResult 需要 (interface{}, string) |
| 10 | `h.sourceSvc.listEnabled()` | SourceService 只有 `List()`，无 listEnabled |
| 11 | `searchSvc.Search(bookURL, keyword)` 参数顺序错 | 实际是 `(query, bookURL, limit)` |
| 12 | `"models" imported and not used` | unused import |

## 2. 根因分析

- **两套模型**：`internal/models`（RuleEngine 使用）和 `models`（Bookshelf/Reader Service 使用），engine.go 中混用了两者
- **字段名差异**：internal/models.BookItem 的 URL 字段叫 `URL`，models.BookItem 叫 `BookURL`
- **重复声明**：之前有旧版 stub handler（doReaderOpen, doSwitchScan），后来重写了新版本但未删除旧的
- **服务方法不存在**：SourceService.listEnabled()、ReadingSession.OpenSession()、RuleEngine.BrowseBooks() 均未实现

## 3. 逐项修复

### 3.1 ReadingService 新增 OpenSession/GetSession (`reading_service.go`)

```go
func (s *ReadingService) OpenSession(sess *ReadingSession) { ... }
func (s *ReadingService) GetSession() *ReadingSession { ... }
```

FFI 引擎直接操作 ReadingSession 而不是经过 OpenBook(ctx, url)，避免 context 传递。

### 3.2 RuleEngine 新增 BrowseBooks (`rule_engine.go`)

```go
func (re *RuleEngine) BrowseBooks(ctx context.Context, source *models.BookSource, searchURL string, category string) ([]*models.BookItem, error)
```

使用 ExploreRule 解析 HTML，同 SearchBook 结构提取 Name/Author/Intro/CoverURL/BookURL。

### 3.3 ContentSearchService 新增方法 (`search_service.go`)

```go
func (s *ContentSearchService) IndexedChapters(bookURL string) int
func (s *ContentSearchService) FTSAvailable() bool
```

前者查 COUNT(DISTINCT chapter_title)，后者查 sqlite_master。

### 3.4 models.Chapter 增加 WordCount 字段

`models/chapter.go` 中添加 `WordCount int`，与 internal/models 对齐。

### 3.5 engine.go 全局类型修复

所有 `models.*` 改为 `internalmodels.*`：
- bookToMap / chapterRow / bookToMapFull / parseBookItem → `*internalmodels.*`
- doReaderOpen / doReaderContent / doBrowseBooks / doSearchStart → `[]*internalmodels.*`
- BookshelfService.Add() 适配：parseBookItem 返回 internal 模型后手动构造 models.BookItem
- doSwitchSeeds：items 是 `[]map[string]interface{}`，手动遍历取值构造内部模型
- doBookshelfAdd/Update：book.BookURL → internalBook.URL
- doBrowseCategories：移除对 SortList/FilterList 的引用（ExploreRule 没有这些字段）
- doReaderSearchContent：修正 Search(keyword, bookURL, 50) 参数
- doRssArticle/doReaderSearchContent：补上 okResult 缺失的第二个参数 ""
- 删除重复的 doReaderOpen(711行) 和 doSwitchScan(700行) stub
- 删除未使用的 `"github.com/legodo-booksource/legodo_go/models"` import

### 3.6 MinGW-w64 工具链修复

由于 cgo 需要 gcc.exe，通过 `cp -r /d/msys64/msys64/mingw64 /c/mingw64` 复制到标准路径解决 cgo 找不到 cc1 的问题。

构建命令：
```bash
export GOCACHE="/d/dev-cache/go-build"
export PATH="/c/mingw64/bin:$PATH"
CC=/c/mingw64/bin/gcc.exe CGO_CFLAGS="-I/c/mingw64/include" \
CGO_LDFLAGS="-L/c/mingw64/lib" \
go build -buildmode=c-shared -o legodo_engine.dll ./pkg/ffi/
```

输出：`legodo_engine.dll` 39MB，编译零错误。
