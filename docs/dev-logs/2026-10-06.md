# 第七十七轮 收：36 处硬编码宽度，先量清楚"客户端到底怎么处理窄"

上一轮（第七十六轮）只收了四处在**页面上**的窄窗降级。这一轮收用户那句
「把 36 处硬编码宽度收一遍」——但收之前先把一件事量明白：**定宽在窄窗里到底会不会坏**。
不量就动手的话，本轮会写出三处多余代码、漏掉一处真裁切（下面 §4 那两处"想当然"就是
量出来之后撤掉的）。

## 1. 判据重画：定宽分三类，只有一类是真缺陷

普查脚本 `.probe/census_narrow_rows77.py`（离线，24 棵目的地树，控件不挂窗口实例化）。
三条契约**每一根都是桌面 release 客户端当场量出来的**：

1. **容器 / 弹层 / `Stack` 子项写定宽 → 不是缺陷**。客户端把它们**夹到父框宽，内容照窄框
   重排**。侧栏抽屉那条：`width=320` 塞进 304 客户区，面板画出来 **284**（= Stack 自己的宽），
   头部那行的 `+`/`✕` 跟着面板右移同样的像素——重排，不是画在 320 上再切右边
   （`.probe/probe_side_clamp77.py` 两臂）。
2. **不换行 `Row` 里的定宽子项 → 真裁**。照字面排完再被父框切掉。正对照：两块各 1184px
   的色条塞进 1104px 的框，第二块色条右端采样到 **−1**（整只没了）。
3. **`ft.Switch` 的 label → 永远不换行**。本轮试过 `label=ft.Text(...)`，与裸字符串
   **两张图完全重合**（304 档，`out_dlg77z_reader_settings_320.png` 对
   `out_dlg77y_reader_settings_320.png`）——开关把标签按无限宽排，包一层控件不管用，
   只能自己拆行。

所以"36 处"里绝大多数（给容器、给抽屉、给弹层写的那 30 处）按第 1 条**原样留着**，
本轮真正动手的是 5 处，全在第 2/3 条那一层。

## 3. 朗读条：`col` 的份额算不出来，量了两轮

第一版按"栏宽 × col/12"算，给 音色 7 / 语速 5，写进注释的是 165 与 118——**两个数都是错的**。
`.probe/probe_readaloud_cell77.py` 把四格各涂一色、逐列扫跨度，另放 5:7 两块纯色当尺子
（三档量得比值 **1.405 / 1.417 / 1.414**，应有 1.400 → 读数不是中间态）：

| 客户区 | 四格实测 | 定宽 150 / 110 / 122 够不够 |
| --- | --- | --- |
| 1184（lg） | 474 / 186 / 186 / 282 | 够，一行排完 |
| 344（xs） | 304 / 175 / 124 / 304 | 够 |
| 304（xs） | 264 / **152 / 107** / 264 | 语速格 107 < 110，**下拉右端被裁 3px** |

差的那 10px 来自朗读条自己的 `padding=10` 与栅格 spacing——这套扣减没写在任何文档里，
**算出来的"够"和量出来的"不够"正好判反**。第二版改成 音色独占一行（`xs=12`）、语速与
连读并排（各 6）：304 档量到 264 / 130 / 130，四格全 ≥ 自己的定宽，**行数没变多**（还是三行）。
两档人看图确认：`out_dlg77x_reader_read_aloud_360.png` / `_320.png`。

## 4. 撤掉两处想当然（都是加了之后量出来才撤的）

- **侧栏抽屉的 `page.width` 夹宽**：见契约 1，客户端自己夹，代码删掉，只留一条注释写为什么
  不用夹。
- **阅读设置面板去掉 `width=420`**：去掉之后**宽窗反而坏了**——整块塌到 280px，
  "左对齐"截成"左对"（`out_dlg77A_reader_settings_1200.png`）。420 恢复，改的是那一头
  真正出界的长标签（契约 3）。两档重测：1184 档框 468 / 高 678，304 档框 256 / 高 690，
  逐张人看无截字。

顺带记一条仪器事实：**`page.width` 就是客户区、跟着拖窗实时变**（真应用里 900→884、360→344，
截图宽度与它一致，两次 resize 事件，`.probe/probe_page_width77.py`）。但在 `main()` 里设
`page.window.width` 的探针上它读到过期的 1264——**窗口是异步生效的**，可用宽要么活拖一次
再读，要么直接从截图量。

## 5. 护栏：`tests/test_narrow_window_layout_contract.py`（12 条）

三条判据钉"没发生"，不钉"失败了"：

- **R1**：`Row(wrap=True)` 里挂了**显式传过 `expand`** 的子项（`expand=False` 也算）→ 整条画成灰块。
- **R2**：`Row(wrap=True)` 挂在 `ResponsiveRow` 格子的**任何一层后代**里 → wrap 行在松约束下
  塌成固有宽（同一位置两臂：格子里套 wrap 只排到 264px 就换行、右边空着 400px；换成不换行
  Row 三件立刻排回一行，而格子本身量到 665px——**该给的宽给了**）。
- **R3**：不换行 `Row` 里若干定宽子项合计超出 `NARROW_BUDGET = 284`（320 窗口 → 客户区 304
  → 去页边距 20）。**单个**定宽子项不算违例（契约 1）。

台账 `ALLOWED` 是**空表**：全库 24 棵目的地树建成 24、失败 0、**命中 0 处**。
变异核验：把 HEAD 上改前的 `read_aloud_bar.py` / `rss_view.py` 拷回来 → **2 条红**，
红的理由各对上一条（R2 套 wrap、R3 定宽兄弟超预算），改回来 12 条绿。
`MutatedRealShapesTests` 那两条不是合成形状，是**把真控件重新套一遍**，防的就是"判据只
对假树成立"。
