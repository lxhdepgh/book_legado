# 开发日志 2026-10-03

> 本轮只有**第六十七轮**一轮：给书源列表页工具栏那颗「自愈」按钮接上书源与章节
> 选择器。此前它只是 `on_open_repair` → 跳到 `sources.repair`，而那一页进页后永远
> 停在"等待自愈报告…"——它自己起不来一轮诊断，只能等阅读页出错时顺带送来的报告。

## 一、这一页原来缺的不是控件，是"能自己起手"

自愈的整条流水线早就在了（`rule_repair.diagnose_content_rule` 真抓 1-3 页样本 →
挖候选 → ProbeEngine 本地回放 → 复核 → 出报告 → 用户点确认才写回），缺的是入口：

- `RuleRepairController` 只订阅 `RepairReportReadyEvent`，报告是别人（阅读器）发起的；
- 视图上连"选哪个源、拿哪一章做样本"的控件都没有，而 `repair(source, chapter)`
  必须要一条**正文页地址**。

章节地址这一格是本轮真正的难点：自愈页不许联网列目录（那是"点开列表页就开始抓站"，
第六十五轮的杀软拦截记忆就写在这条边上），所以只能拿**本地已经有**的东西。三条来源，
全部零联网：

| 顺序 | 来源 | 覆盖面 | 落点 |
|------|------|--------|------|
| ① | 书架那本书的**已缓存目录** | 读过的源 | `rule_repair_service.py:141 chapter_candidates()` |
| ② | 上一轮**检测抽到的样本章** | 检过、没读过的源 | `source_check_service.py:535`（快照多带一栏）+ `rule_repair_controller.py:264 _check_sample_group()` |
| ③ | 用户**手填一个正文页地址** | 前两条都空的源 | `rule_repair_view.py:208 set_manual_visible()` |

②是把已经付过的钱再收一次：检测轮里 `_sample` 已经抓过几章，那几条地址原本只活在
结果字典里、跑完就丢，现在随快照留下（`CheckFinishedEvent` **不加键**——它只有五个
字段，多一个就是 TypeError，护栏里专门钉了这条）。

## 二、载荷走既有的 `load_record`，不新造对话框

列表页勾了哪一源，跳过去就该带着它：`book_source_list_controller.py:272 _start_repair()`
把选中集排序后取第一条，经 `on_open_repair({"source_url", "source_name"})` 发出去，
导航层按既有约定回调目的地的 `load_record`（`rule_repair_controller.py:210`）。
多选时如实说"自愈一次只诊断一个源，已带入 …"，不默默丢掉其余的。
**章节不许从列表页传**——那一页手上既没目录也没检测样本，硬凑的键名只会让自愈页去猜。

界面形状：工具行 `书源下拉(320) + 正文章节下拉(360) + 刷新 + 开始诊断 + spinner`，
`wrap=True`；空态文案从"等待自愈报告…"换成
`选一个书源和一章正文；自愈只给候选，写回要你确认。`（`rule_repair_view.py:25`）。
红线没动：`app/views/source/` 零 `app.services.*` import（AST 扫描仍在护栏里），
`app/services/rule_repair.py` 是 M2 冻结副本、逻辑零改动，写回仍然只在用户点
「应用并重试」之后。

一处**故意留下的不对称**：`update_source_rule` 不发 `SourceChangedEvent`，所以写回
成功后列表页要手动刷新才看得到——状态行里直接写明，不假装已经同步。

## 三、浏览器探针抓出来的真 bug：整族下拉都在读一个不存在的字段

第一版探针（`.probe/probe_repair_picker_ui.py`，WEB_BROWSER + Playwright 点语义树）
在真浏览器里点书源下拉、点候选，Python 侧回的是：

```
[py] on_source_picked(None) → 章节 0 条、粘贴框 visible=True
```

用户明明点中了"备份源 二"，程序收到 `None`。根因不在本轮新写的控制器，在视图那一行：

```python
on_select=lambda e: self._fire(self.on_source_picked, getattr(e, "value", None))
```

flet 0.86.5 的事件对象是 `flet.controls.control_event.Event`，字段只有
`name` / `data` / `control`（外加两个 property），**没有 `value`**；`getattr(..., None)`
于是静默回退成 `None`。全仓 `app/views/` 扫下来这种读法有 **6 处 / 4 个文件**：
`rule_repair_view.py`（书源、章节）、`code_editor_view.py`（书源、规则字段）、
`webdav_view.py`（远端备份包）、`export_view.py`（已缓存书籍）——四条页的选择器在真
界面上点了都没反应。

为什么一直没被发现：测试替身比真事件**多一个字段**。`tests/test_source_rule_editor.py`
里 14 处、`tests/test_tools_chains.py` 里 2 处都是

```python
view._source_dd.on_select(SimpleNamespace(value="https://a/"))
```

`SimpleNamespace(value=…)` 恰好喂饱了 `getattr(e, "value")`，于是界面面 16 条测试全绿。
本轮把 6 处读法改成 `e.control.value`（同仓内一直正确的写法，如
`appearance_view.py:105`、`reader_view.py:950`），并把那 16 处替身换成
`ft.Event(name="select", control=dropdown)`——改完当场红了 22 条，正是替身掩盖的量。

护栏补两头（各自落在自己的射程里）：

- **行为**（`tests/test_views_source_m3.py`）：`test_picking_the_source_by_hand_reloads_chapters`
  与 `test_start_diagnosis_passes_chapter_followers_and_book` 都构造**真** `ft.Event`
  打 `on_select`，断控制器槽拿到的是选中项的键、章节跟着换 —— 上面那两条下拉各一条。
  程序改 `dropdown.value`（列表页带源进来那条路）**不触发** `on_select`，所以它俩
  钉的是不同的路，不能相互替代。
- **静态**（`tests/test_controller_service_surface.py`，与 flet 控件名/枚举/参数同一文件）：
  一条反射 `dataclasses.fields(flet.Event)` 证明 `value` 这个字段本来就不存在，
  一条 AST 扫 `app/views/` 里所有 `on_*=lambda e:` 形参与 `e/ev/evt/event` 具名形参，
  出现 `getattr(x, "value", …)` 或 `x.value` 就报。

## 四、版面取证：下拉在语义树里是一个"没有字的按钮"

同一只探针顺手量出两件静态测试照不到的事（截图 `.probe/out_repair67_1..7.png`）：

1. **语义树里没有下拉的文字**。两条下拉是 `role=button` + `aria-expanded` 的节点，
   rect 分别 `[10,54,320,48]`、`[338,54,360,48]`，`aria-label` 与 `textContent` 全空
   （值只画在 canvas 上）。第一版探针按"书源"两个字找节点，永远找不到——要点它只能
   按属性 + 坐标。顺带一句：读屏软件在这一页念不出选中了哪个源。
2. **合着的框截字，展开的菜单不截**。320/360 定宽下选中值渲染成
   "测试源 po5（正文规则坏了的那一…"、"第2章 这一章的名字长得足够长，看看截…"，
   而展开后的候选行是整行的："第1章 这一章的名字长得足够长，看看截不截" 完整可见，
   加上 `enable_filter` 能打字收窄，所以定宽截字这一条**判为可接受**，没改宽度。
3. 窄屏 430px：`wrap=True` 生效，书源 / 章节+刷新 / 开始诊断+spinner 换成三行，
   没有互相截断。
4. 在途形状：点「开始诊断」后按钮 `disabled`、spinner 支起来、状态行是阶段字；
   **再点一次派发次数仍是 1**（disabled 的按钮不触发 `on_click`，所以"报告就绪"这一拍
   探针借刷新按钮演）。
5. 修完事件形状之后的黄金路径实测：
   `on_source_picked('https://b.example/second') → 章节 3 条、粘贴框 visible=False` →
   `on_chapter_picked('0:1')` → `get_selection={'source_url': 'https://b.example/second',
   'chapter_key': '0:1', 'manual_url': ''}` → 在途 → 报告卡（原规则 `.con@html` /
   新规则 `.con@html||.content@text` / 忽略 + 应用并重试）。

另一处只有真浏览器能教的：语义树是**分帧**建的，第一拍只有 3 个节点时也算"有点数"，
`if count: break` 会在树没长齐就开始点。探针的收工条件改成"≥8 且连续两拍不再变"。
