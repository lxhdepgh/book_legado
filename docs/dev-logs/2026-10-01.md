## 第六十五轮：10054 收尾竞态——归因定了，噪声与句柄一起收（任务 #31/#32）

### 一、现场那两族，身份先说话

两族都带 `循环[engine]线程=legado-engines loop=0x…`：

1. `Exception in callback _ProactorBasePipeTransport._call_connection_lost(None)`
   + `ConnectionResetError(10054, '远程主机强迫关闭了一个现有的连接。', None, 10054, None)`，
   asyncio 自己那份 dump 的 traceback 末行是 `proactor_events.py:165
   self._sock.shutdown(socket.SHUT_RDWR)`；
2. `Future exception was never retrieved` + `ClientOSError(1,
   '[SSL: APPLICATION_DATA_AFTER_CLOSE_NOTIFY] …')`，经 `sslproto.py:651 _do_shutdown`
   → `ssl.py:920 unwrap`。

第五十三轮那次"只加身份、不滤一条"的决定在这里兑现了：**两家都判给 engine 循环**，
Flet 的 websocket 洗清嫌疑，下一步该看的是 aiohttp 会话的收尾，不是界面。

`(None)` 那半段还多送一条信息。`Handle._run` 的 message 是
`f'Exception in callback {cb!r}({args!r})'` 拼出来的，args 是回调的实参——
`_call_connection_lost(None)` 说明这次收尾是从 `close()` / `abort()` / `_force_close(None)`
排进来的（读/写路径会把异常本体带进 args，形如 `_call_connection_lost(ConnectionResetError(...))`）。
也就是**我们主动关的连接**在对端已经复位之后收尾，不是被动断线。

关键判断：这轮扫描**一条请求都没失败**。所以它是竞态噪声，不是业务故障——但"噪声"不等于"无害"。

### 二、频率：离线复现不了，而且能证明为什么复现不了

`.probe/loop_teardown_matrix.py` 把 **状态 × 收尾动作 × 对端复位时机 × 延时** 摊开：
idle / paused / silence / unread / tls 五种连接状态 × `close` / `abort` / 先 IO 再 `close`
三种动作 × 对端 `rst` / `fin` × 0.05 s / 0.2 s 延时 = **44 格**，再加三个 aiohttp 形状
（`session-close` / `connector-abort-ssl` / `reuse-dead`）同样两延时 = **12 格**，
每格 8 次事件。**62 格全部 0 条循环级记录**（合计那行：归属行 0 + default dump 0）；
进程句柄起始 293 → 原始 44 格跑完 288 → 12 格 aiohttp 形状跑完 294（差 +1，**不随事件数涨**）。

不是探针没接上——回环上根本进不了那个状态。同场微测：`sock.shutdown(SHUT_RDWR)` 在
"读完响应再等复位""一口不读就等复位""写完 200 KB 无人读再复位""复位之后再发一个请求"
四种状态下**全部成功返回**。10054 要撞在 `shutdown()` 上，需要**在途未确认的发送数据**；
回环上发送缓冲总被对端协议栈立刻吸走，这个状态在回环上不存在。真链路才有：请求刚写出去、
链路或对端把连接复位，或中间盒注入 RST。

所以这一族的**发生频率**是现场量，本轮不留离线数字（记忆 `docs-numbers-must-be-measured`）。

### 三、后果：复现不了"会抛"，就直接造"已经抛"

`.probe/loop_teardown_cleanup_probe.py`：给 **40 条活着的** proactor 传输层把 `shutdown`
换成抛 10054（`_BoomSock` 代理真 socket，其余方法原样转发），走完 `transport.close()`
那条回调，看 `proactor_events.py:154-172` 那个 `finally` 欠下什么。三臂各 40 事件，本轮实测：

| 臂 | 日志 | 命中后 `fileno≥0` | 句柄轨迹 | `gc.collect()` 后 | ResourceWarning |
| --- | --- | --- | --- | --- | --- |
| A 对照（不抛 + 第 53 轮处理器） | 归属 0 + default 0 | 0/40 | 245 / 245 / 245 | 245 | 0 |
| B 抛 10054 + 第 53 轮那份（现场形状） | 归属 40 + default **80**，每事件 3.0 行 | **40/40** | 251 → 299 → 305 | **303** | 23/40 |
| C 抛 10054 + 本轮换上的处理器 | **1 行 / 40 事件** | 0/40 | 245 / 245 / 245 | 245 | 0 |

B 臂就是现场那份的形状：`shutdown()` 一抛，166 行 `sock.close()`、167 行 `_sock = None`、
172 行 `_called_connection_lost = True` **一行都不执行**。后果是**一次竞态一个不归还的
socket 句柄**（40 事件 → +54 到 +60 个句柄，显式 `gc.collect()` 只收回 2 个，40 次里
只有 23 条 ResourceWarning——`__del__` 那条兜底路靠不住）。全库扫描一轮跑上千次连接，
这个量级就不是"看着烦"而是"越跑越少"。

顺带钉一条测到了什么、没测到什么：`protocol.connection_lost` 被调两次这件事三臂都是 0/40。
每臂一条传输层只 close 一次，155 行那道闸门失效的代价在这个形状里出不来——**不写成"没问题"**。

### 四、改法：认两族、一条带累计计数的短行、族 1 就地补关

`app/core/engine_worker.py`：

* `_teardown_family(context)`：判据按现场那两条 traceback 的**原文**收得极窄——族 1 要
  message 里有 `_call_connection_lost` **且**异常本体是 `ConnectionResetError`/
  `ConnectionAbortedError`；族 2 要 `OSError` 且字符串里有 `APPLICATION_DATA_AFTER_CLOSE_NOTIFY`。
  认错的代价是把真故障折成一行计数，比多打几行严重得多，所以宁可认不出。
* `install_loop_attribution` 的处理器命中族时：按族累计计数，**每次都补关**（族 1），
  日志按 `_TEARDOWN_MIN_INTERVAL = 10.0` s 节流成一条短行（含 tag/线程/loop id/族/累计次数/
  异常本体，明确写"不再逐条打 traceback"），**不再转 `default_exception_handler`**。
* `_finish_socket_teardown(context)`：从 `context['handle']._callback.__self__` 取传输层，
  `fileno() != -1` 就 `close()`，再写回 `_sock = None`、`_called_connection_lost = True`——
  只做 CPython 自己已经决定要做的那三行，不碰别的。
* **认不出的一切照旧**：身份一行 + 原样转给 `default_exception_handler`，一条记录都不许少。
  `keep-alive`、连接池、`session.close()` 的策略本轮**一行没动**（任务 #32 的边界）。

一处设计坑：补关**不能**放进"这次要落日志"的分支里。降频一生效，被折掉的那些事件就漏补，
等于把句柄泄漏换成看运气。现在补关在闸门之外，每事件必补——护栏专门有一条断这个。

### 五、否掉的三条补法（都有证据，别再走一遍）

* `TCPConnector(enable_cleanup_closed=True)`：Python 3.12 上 aiohttp 自己当**死参数**，
  `_cleanup_closed` 那条路在 3.12 分支里不走，装上去什么都不改。
* `force_close=True` / 把 `keepalive_timeout` 调小：那是把"优雅收尾"这条更容易撞上的路
  换成直接 abort，还要赔掉第六十二轮实测过的 keep-alive 收益。方向错了。
* `connector.close(abort_ssl=True)`：`ClientSession.close()` 没把这个参数透出来，要打穿得改
  会话层；而且它改的是**连接池策略**，本轮边界外。
