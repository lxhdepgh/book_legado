## 3. 各服务实现要点

### 3.1 ReplaceRuleService（§1.7）
- **表**：`replace_rules(id/name/pattern/replacement/scope/is_regex/enabled/created_at/updated_at)`。
  `scope` ∈ {content, title}，对应 Legado `isTitle`；`is_regex` 对应 `isRegex`（默认开）。
- **正文应用两级叠加（红线）**：在 `reading_engine.py` 新增模块级注入点
  `set_global_replace_rules_provider(callable(scope)->list)`。服务 on_start 注入、
  on_stop 注销。`process_book_content` 在书源内嵌 `contentReplaceRules` **之后**
  追加全局 content 规则；`chapter_display_title` 在书源内嵌 `titleReplaceRules`
  **之后**追加全局 title 规则——顺序与 Legado ContentProcessor 对齐（书源内嵌先、全局后）。
- **零回归保证**：provider 未注入（None）时 `get_global_replace_rules()` 返回 `[]`，
  正文分支条件退化为原 `if use_replace and content_rules:` 真值判断，逐字节不回归；
  test_legado_compat 486 不减即证。
- **开关**：全局叠加是否生效由 SettingsService 键 `replace.global.enabled` 控制（默认开）；
  关闭时 provider 返回空列表，等同旧行为。
- **事件**：save/delete/set_enabled 后发 `ReplaceRulesChangedEvent(ids=[...])`。

### 3.2 DictService（§1.8）
- **表**：`dict_rules(id/name/url/rules_json/enabled)`。`url` 为释义页模板（`{{key}}` 占位），
  `rules_json` 存 legado 规则（ruleContent 等）。
- **lookup(word)**：把词典规则视为"目标为释义页"的特殊书源——URL 模板 `{{key}}`
  填词后经 RuleEngineService 的 `engine._request` 抓页（复用同一 aiohttp 会话/UA/超时/cookie），
  再用 `legado_rule_parser.evaluate` 抽释义正文。**不另写解析器**。
- fetcher 可注入（测试离线 stub，不联网）。

### 3.3 FontService（§1.9）
- **系统字体枚举**：`_system_font_dirs()` 平台分支——Windows `C:\Windows\Fonts` /
  macOS `~/Library/Fonts`+`/Library/Fonts` / Linux `~/.fonts`+`$XDG_DATA_HOME/fonts`+
  `/usr/share/fonts`；读取/解析统一 fontTools（`TTFont.getDebugName(1)` 取族名）。
- **用户字体**：`add_font_file(path)` 把字体拷进 app_paths 数据目录 `fonts/` 并登记
  `fonts(id/name/family/path)`；`list_user_fonts()`/`remove_font(id)`（删行+删文件）。
- **选中字体**：SettingsService 键 `font.family`（`get_selected_family`/`set_selected_family`）。

### 3.4 QrCodeService（§1.10）
- **generate(text) -> bytes**：`qrcode` 库（ERROR_CORRECT_M，box_size=10，border=2）+
  Pillow 渲染 PNG，返回 PNG 字节流。
- **decode_image(path_or_bytes) -> str | None**：opencv-python-headless `QRCodeDetector`，
  接受图片路径或 PNG/JPG 字节（图片文件/剪贴板截图）。**无摄像头**（桌面无硬件）。
  中等分辨率（~370px）下 opencv 5.x 偶发检测不到定位符，已加"放大 2x 最近邻后重试"兜底。
- 手动输入通道由视图层直接调 SourceService/ReplaceRuleService 导入（本服务不做）。

## 4. schema v5（`_migrate_v5`）

新增四表：`replace_rules` / `dict_rules` / `fonts`(UNIQUE(path)) / `download_tasks`
（book_url/kind/status/progress/files(JSON)）。download_tasks 为下载线预留，本线只建表。
SCHEMA_VERSION 4→5；test_core_lifecycle 断言同步为 5。

- `qrcode>=7.4`：纯 Python（py3-none-any wheel），三端一致。
- `opencv-python-headless>=4.8`：三端均有 wheels——win_amd64（本机实测安装

  传递依赖 numpy（cp312 win_amd64 wheel）。
- 已 `pip install` 到项目 conda 环境 `legodo_booksource_check`。

## 6. 与契约的偏差

1. **replace_rules 表多了 `is_regex`/`created_at`/`updated_at` 列**：契约 §6.3 列草案为
   "id/name/pattern/replacement/scope/enabled"。补 `is_regex` 是为对齐 Legado
   ReplaceRule 实体 `isRegex`（与 reading_engine 现有默认 `isRegex=True` 一致，否则全局
   正则规则无法表达）；时间戳列供管理视图排序。属草案列的合理补全，不违反契约语义。
2. **dict_rules 表多了 `rules_json` 列**：契约草案为 "id/name/url/enabled"。词典规则需
   携带 legado 解析规则（ruleContent 等）才能"当特殊书源抓释义页"，以 JSON 文本存
   `rules_json`，不另立解析器。
3. **QrCodeService 不硬依赖 SourceService/ReplaceRuleService**：契约 §1 依赖列写
   "SourceService/ReplaceRuleService（JSON 互操作）"。实际 JSON 互操作发生在视图层
   （扫码后视图把文本交给对应服务导入/导出），服务本身只做编解码文本，故 dependencies
   为空，避免反向耦合（工具域不依赖书源域）。
4. **download_tasks 表由本线建表**：契约 §14 把它列在 v5，但归属 DownloadService 线；
   按 v4 RSS/tts 同函数追加的先例，本线在 `_migrate_v5` 内一并建好，供下载线直接使用。
