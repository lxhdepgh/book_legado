## 2. 依赖扫描方法（裁决依据）

- 扫描范围：`app/` 全量 + 根 `main.py`，**排除 `tests/`**；AST 解析（`utf-8-sig` 剥离 BOM），含相对导入解析，精确区分同名新模块：
  - `app.services.theme_service`(冻结根) vs `app.services.tools.theme_service`(新外壳)
  - `app.services.book_cache_service`(冻结根) vs `app.services.reading.book_cache_service`(新外壳)
  - `app.views.check_view`(冻结根) vs `app.views.source.check_view`(新视图)
- 另排查 `importlib`/`__import__` 动态解析的 dotted path：全部指向新模块（`app.services.sources.*` / `tools.*` / `content.*` / `engine.rule_engine_service`），无一指向冻结根文件。
- 判定规则（契约 §2）：被**非测试**代码 import 的冻结文件 = 核心资产，原位保留；无任何非测试引用 = 旧单体残留，删除；不确定一律保留。

## 7. 与契约的偏差记录

1. **冻结根 `book_cache_service.py`/`reading_progress.py` 实际未被新 M2 服务 import**：契约预期"若 M2 服务仍 import 则保留"；实测新外壳把内层逻辑自 `old_code/` 内联复写进 `app/services/reading/*`，并未 import 冻结根副本，故按规则删除（与契约"已复制则删"分支一致）。
2. **`test_ui_safety` 红线 #6 增加白名单**：契约字面"服务零 flet"，但保留核心资产 `web_page_renderer.py` 确为 BrowserService 授权 UI 桥接（in-app WebView/投屏/验证码）。lint 据此设唯一白名单，其余服务 shell 零 flet，既守门又不与现状矛盾。
3. **删除契约未逐一点名的两个活跃测试**（test_reader_ux/test_theme_service）：它们 import 已删旧视图，M7 全绿要求下必须退役，已在 §5 说明理由；纯服务逻辑测试（test_rule_repair）已外科保留。
