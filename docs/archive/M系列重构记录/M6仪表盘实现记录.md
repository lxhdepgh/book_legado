## 2. 功能落地（对照契约 §5 / 设计 §4.5）

- **服务列表**：`ServiceHub.status_report()` 快照逐行渲染——服务名 / 状态（带状态色）/ 进度（0-1 → 百分比）/ 最近错误 / 启动时间，M1 五列保留。
- **启停控制**：每行新增"操作"列，三个 IconButton（挂起 / 恢复 / 停止）。
  - 经 `hub.service_by_id(service_id)` 取**原始 Service 实例**，调其 `suspend()/resume()/stop()`（基类 async 方法，见 lifecycle.py）；
  - 协程对象统一经 `EngineHub.submit`（`run_coroutine_threadsafe` 投到守护线程 loop）fire-and-forget，**Flet 事件线程不阻塞、不 await**（§4.3 请求-响应规则）；默认派发器 `engine_hub().submit`，测试可注入；
  - 按钮按状态机裁决可用性：RUNNING → 可挂起/停止；SUSPENDED → 可恢复/停止；其余态禁用；ServiceHub 自身那一行（status_report 首行）无可控实例，三按钮恒禁。
- **事件流面板**：订阅 `ServiceStateChangedEvent` + `SettingsChangedEvent`（§4.3 冻结事件表），`collections.deque(maxlen=50)` 环形缓冲最近 50 条，新事件置顶；状态事件到达时同步重读快照刷新服务表（实时可见，§4.5）。
- **attach/detach 对称**：构建视图即 attach（订阅 2 类事件 + 首渲染）；返回的 `ft.View` 挂 `view.detach()`，导航方切换目的地离开时调用即对称退订（§7.4 防跨页泄漏），重复 detach 幂等。
- **边界**：视图只经 hub 公开接口（`status_report` / `service_by_id` / `bus`），不 import 任何 `app.services.*` 实现类，不持有服务实例列表。

## 3. 线程与测试模型

- EventBus 只收 async handler 并派发到 EngineHub 守护线程；handler 内直接改控件属性——与既有 `CheckController._on_check_finished`（M3）、`ReplaceRuleController`（M5）同款写法，不做额外 UI 线程 marshal。
- 离线测试不拉起 Flet 窗口：ft 控件无窗口可实例化；hub/bus/submit 全部 stub 注入；控制派发用 `asyncio.run(coro)` 同步跑掉协程断言 stub 记录。

## 4. 与契约的偏差（需集成方知悉）

1. **`ServiceHub` 增量补 `service_by_id(service_id)`**：契约 §5 要求"启停控制经 hub"，但既有 hub 的 `get(stype)/require(stype)` 均按**服务类**定位，而 `status_report()` 行里只有 `service_id` 字符串——不补此通道，仪表盘无法从一行反查到可控制实例。新增方法为**纯只读增量**（遍历 `_services` 按 `name` 匹配，未注册返回 None），不改任何既有行为；Agent A/B 不受影响。视图未碰私有 `_services`。
2. **文件位置**：契约 §5 写"views/settings/service_dashboard.py（或 views/tools/）"，按本线任务明确要求仍落在 `app/views/service_dashboard.py`（原地替换 M1）；~~`views/settings/` 目录当前为空，导航线如需迁包由其调整导入~~——2026-09-27 复核：该目录现有 `appearance_view.py`（外观页正式视图，经 navigation.py:97-103 工厂装配），"空目录"陈述已失效；service_dashboard 本体位置未再迁移。
3. **视图形态**：契约 §5 提"删除旧 service_dashboard.py 或改由新视图承接"——本线原地替换承接，main.py / registry.py 既有引用零改动。
