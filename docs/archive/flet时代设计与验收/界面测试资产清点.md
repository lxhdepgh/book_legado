## 1. 一个决定全局走向的读数

**28 个 flet 测试文件里，`ft.run` / `AppView` / `flet_desktop` 出现 0 次。**

```
grep -rcE 'ft\.run|AppView|flet_desktop' tests/*.py | grep -v ':0' | wc -l   # → 0
```

也就是说：今天这套"界面测试"**没有一条真的起过窗口**。`ft.Page` 一律是内存替身
（`_FakePage` / `SimpleNamespace` / `MagicMock`），断言读的是**Python 对象树上的属性**
（`.value` / `.visible` / `.controls` / `.options` / `page.update` 次数），
像素、语义树、真实排布这些"用户真正看见的东西"从来不在这个面上——它们活在 `.probe/`
那 37 支手动探针里（§6）。

推论决定了这份清单的形状：

1. 迁移删掉 `app/views/` 时，这 1854 行断言**整体随实现一起消失**，
   不存在"搬过去"——只有"在 Dart 侧重写一份等价物"或者"认了，没有等价物"。
2. 所以真正要判的只有一件事：**这条断言钉的性质，在 Flutter 侧存不存在同一个观测点**。
   存在 → 重写（A）；不存在 → 明确放弃（B）；性质本来就与前端的无关 → 留在 Python 侧（C）。
3. 记忆 `flet-0-86-api-surface` 那条老教训在这里第二次生效：**静态读树属性的测试全绿，
   不等于界面是对的**。A 堆翻译过去之后，Dart 侧的 golden 才是界面面的第一手证据，
   别让翻译版的 widget 测试冒充它。

## 2. 分类口径（三条，互斥；一行归一堆）

| 堆 | 判据 | 迁移后的去处 |
| --- | --- | --- |
| **A 可翻译** | 钉的是**用户看得见/摸得着**的性质：控件在不在、可见性、文本内容、下拉选项集合、开关状态、按钮禁用、列表行数、页签与导航结构、宽/窄档下的行列结构 | Dart `widget_test`（`find.text` / `find.byType` / `expect(findsNothing)`）；带尺寸预算的那几条落 **golden** |
| **B 明确放弃** | 钉的是 **flet 这个框架自己**的性质：`page.update()` 下发次数、控件对象身份、`controls.clear()` 这类内部机制、flet 版本特定的构造参数、依赖真客户端往返的观测（`on_scroll` 回上来的 `pixels`、语义树、实拍） | 无对应观测点。Flutter 侧要同类保证得**另立判据**（见 §5），不许把老断言折成新断言 |
| **C 留在 Python 侧** | 钉的其实是控制器/服务的编排与状态机（调了哪个服务方法、事件发了几次、任务取没取消、预算超没超、数据落没落库），只是**顺手**用控件属性当观测点 | 不随前端迁移；G4 之前应改成 flet-free 断言（读服务状态/事件流水，不读树） |

优先级按 B > C > A 落（一条断言同时像两堆时，先落更"硬"的那堆），所以表里的 A 数是**上限**：
里面还混着 **28 条** `assertIsInstance(…, ft.Column/Row/Control/View/Stack)`
（"能嵌进页签的容器种类"这类；同一面上另有 24 条断言的是 `ft.Dropdown`/`ft.Image`/`ft.Text`
等具体控件种类，合计 52 条身份断言，全部数自那 28 个文件）。Dart 没有 Column-vs-View
这个观测点，真正翻译时它们会滑进 B。

## 5. 三堆各自的具体处置

### A（1315 条）——不是"搬"，是"在 Dart 侧重写一遍"

按可译性再切一刀，避免把"树属性断言"当成"界面断言"翻译：

- **直接有对应物**（可见性、文本、选项集合、禁用、行数、页签结构）：
  Dart `widget_test` 一对一重写；每条的验收判据写成**语义层**（找得到/找不到那个
  可见文本或控件类型），不写 flet 的类名。
- **只有形状、没有像素**（窄窗那 13 条 `test_narrow_window_layout_contract`、
  工具栏 col 栅格、档位通道）：Dart 侧必须落成 **golden**（同尺寸同内容比像素），
  因为原断言的判据本身就是"当场量出来的"（那份文件的 docstring 明写 R1/R2/R3 每条
  都来自桌面实拍）。把 golden 换成"属性等于常量"就是假等价。
- **那 28 条容器种类身份断言**（`assertIsInstance(view, ft.Column/Row/Control/View/Stack)`）：
  Dart 没有"能嵌进页签的容器种类"这个观测点，翻译时会滑进 B。别为它们发明一条新断言来凑数。

### B（69 条）——明确放弃，逐类写清"为什么没有等价物"

| 类别 | 条数（主要落点） | 为什么放弃 |
| --- | --- | --- |
| 下发次数 / `page.update` 记账 | `test_resize_band_gate`（11）、`test_appearance_theme` 部分 | 钉的是 **flet 的编组机制**（服务端→客户端的消息下发）。Flutter 是渲染树自己 diff，没有"这一拍有没有下发"这个可观测事件 |
| 控件对象身份 / `controls.clear()` 等内部机制 | 散在 `test_views_*` | Python 对象身份在 Dart 侧不存在 |
| flet 版本特定构造参数 | `test_appearance_theme`（12 里的多数）、`test_views_navigation_m6`（5） | 钉的是 flet 0.86 的 API 形状（如 `Tabs.length` 必传、`Dropdown` 用 `on_select`），换了框架这些名字本身没了 |
| 依赖真客户端往返的观测 | `on_scroll` 1 条、`scroll_to` 2 条、`pixels` 9 条（含在各类里） | 老断言里这批发的是内存假页，本来就没真往返；真往返的证据在探针侧，Flutter 用 `integration_test` 重做（见 §6） |

放弃不等于没有保证：**同档不重发**这类性质在 Flutter 侧的正确判据是"帧时间/重建计数"
（`Timeline` + `rebuilds`），那是新的一条测试，不是老断言的翻译版。这条差异要写在 G1 的
验收里，别在割接当天才发现两边量的是不同的东西。

### C（470 条）——留在 Python 侧，但要先把观测点从树上挪下来

三个文件整堆落 C：`test_check_depth_tiering`（87）、`test_reader_video_panel`（43）、
`test_browser_render_chain`（26）；`test_controller_service_surface`（9）整堆是 C 且**本来
就是 flet-free 的 AST 对齐**。这批的性质（分片、欠债队列、投屏接线、服务派发）与前端无关，
迁移后仍然要有护栏，但断言得改成读服务状态/事件流水。改的时机是 **G4 删 `app/views/` 之前**，
否则删视图那天会连带把这 470 条一起删掉——那才是真正的资产损失。

## 6. 探针资产（界面的"第一手证据"其实全在这里）

```
grep -rlE 'async_playwright|chromium\.launch|from playwright' .probe/*.py | wc -l   # 19
grep -rlE 'ft\.run\(' .probe/*.py | wc -l                                          # 37
```

- **19 支 Playwright/语义树探针**（`probe_text_semantics_shape`、`probe_repair_a11y_label`、
  `probe_repair_manual_a11y`、`probe_repair_mount_no_semantics_error`、
  `probe_selection_area_copy`、`scroll_key_column_attr`、`check_toolbar_depth_layout`、
  `paragraph_*`/`jump89_*`/`size_change_height_attr`/`relayout_anchor_attr` 等）：
  仪器是"浏览器 + a11y 语义树"，flet Web 视图专用。Flutter 侧的对应物是
  `integration_test` + semantics（`SemanticsBinding`），**要重写，不是搬**。
- **37 支起 flet 客户端的手动探针**（`probe_drag78*`、`probe_resize_*78`、
  `probe_portrait_*75/77`、`probe_wrap_expand76`、`probe_readaloud_cell77`、
  `probe_rss_shape80`、`probe_bosskey_*`、`probe_background_paint74`、
  `probe_exit_code_attr78`、`r4_ui_baseline` 等）：这一批就是本仓库界面测量的**仪器库**，
  第七十八/七十九轮的每拍成本、第八十/八十一轮的回归都从它们出。迁移期间它们的价值反而上升：
  G1 之后"同一份书单的两臂对照"要靠同一支探针把 flet 臂再跑一遍（见 §7）。
- 附带的 300+ 张 `out_*.png` / `*.log` 产物键在 flet release 客户端渲染上，
  是上面 B 类断言的证据链源头；Flutter 侧要重拍，不能沿用。

## 7. 这份清单怎么被用（割接纪律）

1. **G1–G3 期间一行都不删**：flet 面还在服务用户，1854 行断言是现状的护栏。
2. A 堆按屏翻：G1 一屏（书架）→ G2 找书/换源 → G3 阅读器，每道门交付"这屏的 Dart
   测试覆盖了 A 堆里属于这屏的哪几条"的对照表，缺项写进那道门的验收。
3. C 堆那 470 条在 **G4 之前**改成 flet-free（读服务状态/事件，不读控件树）。
4. B 堆 69 条在 G4 随 `app/views/` 一起删，删除清单里逐条写"这条的性质改由 X 保证"
   或"这条不再保证，因为 X"——"不再保证"也要写下来，别让它静默消失。
5. 每道门都要能回答"继续还是退回"：退回成本在 G4 之前仍是零（flet 一行没删）。
