## 2.10 QuickJS 看门狗 —— 已实现

- **处置**：在 `_QuickJsDispatcher` 入队与执行处记录墙钟时间，排队/执行超时统一取消 future。
- **改动内容**（`app/services/engine/legado_js.py`）：
  - `submit()` 任务元组末尾追加 `time.monotonic()` 入队时刻（`sequence` 唯一，不破坏 PriorityQueue 比较）。
  - `_serve()`：出队后先判排队超时（`QUEUE_TIMEOUT=30s`），超时即 `future.set_exception(TimeoutError)` 并丢弃，不再执行；
    后台任务（priority!=0）曾加 `BACKGROUND_MIN_INTERVAL=0.05s` 最小间隔限速——
    **该限速已在 2026-09-29 第三十八轮删除**（那条睡写在出队之后，前台任务此刻正排在
    队列里等这条线程醒来，既没保护前台也白白闲置串行资源；实测前台插队等待
    58ms → 6ms，40 次后台求值 2727ms → 760ms）。前台的保护本来就由 PriorityQueue
    的排序给出。
  - 新增 `_watchdog()` 后台线程：执行超过 `EXECUTION_TIMEOUT=30s` 时释放调用方 future（记 `last_error`）。
    QuickJS 原生 runtime 绑死单线程、无法硬中断运行中的 JS，故 worker 线程仍在跑，但调用方不再永久挂起。
  - 前台(0)/后台(1)优先级顺序不变。
- **涉及文件**：`app/services/engine/legado_js.py`（`_QuickJsDispatcher` 类）。
- **验证**：导入 OK，dispatcher 具备 `_watchdog`；死循环源不再无限阻塞后续阅读。

## 2.13 超时三档 —— 已实现

- **处置**：`aiohttp.ClientTimeout` 升级为 total + connect + sock_read 三档。
- **改动内容**（`app/services/engine/rule_engine.py` `_request_transport`）：
  - `connect` 默认 `DEFAULT_CONNECT_TIMEOUT=15s`（调用方显式传 `connect_timeout` 时优先）；
    `sock_read` 默认 `DEFAULT_SOCK_READ_TIMEOUT=60s`；`total` 默认 `DEFAULT_TOTAL_TIMEOUT=90s`，
    调用方显式传 `timeout` 时优先（视图层换源/找书短超时 10s/5s 覆盖不变）。
  - aiohttp 无独立 write 超时，写阶段由 sock_connect + total 覆盖。
- **涉及文件**：`app/services/engine/rule_engine.py`、`app/services/engine/_prefs.py`。
- **偏差说明（集成订正）**：实现最终形态为——`ReaderEngine.__init__(timeout=None)` 时 total 兜底 90s
  （`DEFAULT_TOTAL_TIMEOUT`），显式传值保持调用方控制；与设计文案"total 兜底 90s"一致，
  视图层短超时经显式传参不受影响。
- **验证**：`test_engine_timeout_three_stage_total_connect_read` 断言
  total=15（显式）/connect=15/sock_read=60（旧断言 connect=None，属预期行为变更，集成方已更新用例）。

## 2.15 Cookie 双罐合一 —— 已实现

- **处置**：aiohttp 自带罐关闭合并（仅留连接池）；请求 Cookie 头统一走 `export_cookie_header` 单点；
  持久层迁移 SQLite（软接入），未初始化回退。
- **改动内容**（`app/services/engine/rule_engine.py`）：
  - `_session_for()`：会话 `cookie_jar=aiohttp.DummyCookieJar()`，不再用逐源 `CookieJar`；
    请求 Cookie 头已由 `self.js.export_cookie_header(url)` 合并（既有单点），响应 Set-Cookie 已由
    `self.js.save_response_cookies()` 单点处理。
  - `_persist_source_cookie_jar()`：SQLite 主路径（`storage_db()` 就绪时把 JS 罐持久 Cookie 快照
    upsert 进 `cookies` 表全局键 `legado_cookie_store`，对标 Legado cookieDao）；未初始化（离线单测/
    无服务环境）时回退旧 `.jar` 写行为（引擎级逐源罐），保证既有测试契约不回归；
    JS 罐自身 persistent_state JSON 保留为读侧回退。
  - `legado_js.py`：`__init__` 在 JSON 无 cookies 且 StorageService 就绪时从 `cookies` 表全局键恢复；
    新增 `persistent_cookie_snapshot()` 供落库。
- **涉及文件**：`app/services/engine/rule_engine.py`、`app/services/engine/legado_js.py`。
- **验证**：`test_source_cookie_jar_persists_between_engine_instances` 走 .jar 回退路径照常通过
  （引擎级逐源罐 .jar 持久化契约保留）；SQLite 路径由集成侧补的落库/恢复冒烟覆盖。
- **集成风险**：`storage_db()` 契约点——core.storage 未就位时回退旧 .jar 行为；表结构（cookies 表）由
  StorageService 定义，本侧软调用、未对齐时静默跳过，不打断规则执行。

## 2.19 可选网络后端 Cronet —— 不修复

- **理由（按设计条目原文）**：Cronet 是 Chromium 网络栈组件（HTTP3/QUIC/BBR），依附 Android 平台分发，
  桌面 Python/aiohttp 生态无等价可切换后端，且红线与打包现状（PyInstaller 单文件）都不支持再捆一个
  原生网络栈；书源流量以 HTTP/1.1/2 文本与小图为主，QUIC 收益面小。弱网/特定 CDN 体验差异由相邻项
  缓解：2.17 连接失败自动重拨、2.13 四段超时、2.18 每主机并发对齐、2.20 全局 UA 可配。
  设置页不设 Cronet 开关。
- **验证**：不新增实现；网络组修复项联回归时间接覆盖。
