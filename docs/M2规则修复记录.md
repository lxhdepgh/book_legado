## 2.3 Java 原子组 / 所有格

**处置：检出 `(?>` 或 `*+/++/?+` 时改用 PyPI regex 后端，普通 pattern 仍走 re。**

- 依赖：venv 内 `pip install regex`（纯 Python 跨平台包），并加入 `requirements.txt`（`regex>=2024.0.0`）。
- `java_regex.py`：
  - 顶部 `try import regex`（缺失时静默降级为 re）。
  - 新增 `_needs_regex_backend(pattern)`：先剥 `\Q..\E` 字面块，再检出 `(?>` 或所有格量词
    （`*+`/`++`/`?+`/`{n}+`）。

  - translate_pattern / translate_replacement 两后端共用，`$1`/`${n}` 语义统一为 `\g<n>`。
- 实测：re 与 regex 标志位数值完全一致（I=2/M=8/S=16/X=64）；`(?>`、`\d++`、`x*+`、`x?+` 均可编译匹配。
- 测试：`TestM2_2_3_JavaPossessiveAtomic`（原子组不回溯、所有格、`\Q..\E` 不误触发、普通 pattern 仍 re、`$1` 替换）。

## 2.5 正文多页 webJs【待确认 → 分支②：收窄一致，仅注释】

**核对动作：** Grep reading_engine.py + rule_engine.py 全链。
- `content_document` 每页循环都构造 `request_defaults={webJs, sourceRegex}`（L1570-1573），
  首页/单链链/多页 `asyncio.gather` 三条路径都把它传给 `_request_value`；
  `_request_value` 用 `request.setdefault` 把 webJs/sourceRegex 并入 request 字典。
- **关键**：`_request`/`_request_transport`/`_apply_request_option_js` 只读 `request["js"]`，
  **从不消费 webJs/sourceRegex 键**（全引擎目录 grep 证实 webJs 仅出现在 reading_engine 赋值处
  与 legado_js 的 JS shim，请求管线无消费点）。
- **结论分支②**：多页 gather 分支并不会真正跑 webJs，与首页/单链行为一致，无需剥离。
  在 `request_defaults` 处补 `[M2-2.5]` 注释记录核对结论。

## 2.12 abs: 前缀【待确认 → 分支②：统一收敛到取值层】

**核对动作：** 构造四组（另加两组）用例跑 `_attr + extract_value` 与 jsoup baseUri 语义比对：

| 用例 | 修复前 | 修复后 | jsoup 期望 |
|---|---|---|---|
| `@abs:data-x` 裸相对 `book/ch1` | `book/ch1`（漏补全）| `https://example.com/novel/book/ch1` | 补全 |
| `@href` 已是绝对 URL | 原样 | 原样 | 原样 |
| `@href` 协议相对 `//` | 补全 | 补全 | 补全 |
| `@abs:href` 相对路径 | 补全 | 补全 | 补全 |
| `@abs:data-x` 已是绝对 | 原样 | 原样 | 原样 |
| `@abs:data-x` 协议相对 | 补全 | 补全 | 补全 |

**结论分支②**：非标属性名 `@abs:data-x` 的裸相对路径漏补全。
- `rule_engine.py`：新增 `_rule_uses_abs_attr(rule)`（取最后一个 `@` 属性段、剥 `attr.` 后判 `abs:` 前缀）；
  extract_value 的 urljoin 条件加 `abs_hint`——`abs:` 来源属性一律按 base_url urljoin，
  不再仅靠"规则名含 url/href/src 或相对路径前缀"启发式。已是绝对 URL 时 urljoin 原样返回。
