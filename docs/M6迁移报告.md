## 1. 迁移对象（4 类旧介质 → 主库表）

| 旧介质 | 主库落点 | 字段映射 | 说明 |
|---|---|---|---|
| `bookSource.json` | `book_sources` | id/name/url/group/enabled/custom_order/check_state/respond_time + json 全文 | v6 建表；检测状态/响应时间列 |
| `bookshelf.json` | `bookshelf` | book_url PK/source_url/name/author/kind/cover_url/in_bookshelf/reading(JSON)/vars(JSON)/updated_at + payload 保旧字段 | reading 块原样保留（回退展示用） |
| `search-books.sqlite3` | `search_books` | book_url PK/name/author/kind/origin/source_group/updated_at + payload | 24h TTL 语义保留 |
| `appearance.json` | `settings`（`appearance.snapshot` 键） | 键并入；不覆盖已存在值 | M5 起 ThemeService 已停写 |

## 2. 迁移机制

- `StorageService.migrate()` 于 `on_start` 调用；只读导入 → 校验（数量/字段缺失清单）→ 旧文件改名 `.legacy-bak`（**不删除**，可逆）。
- 幂等：`settings` 表 `m6.legacy_migrated` 标记，二次 migrate 不重复导入。
- 锁：`_db_lock` 由 `Lock` 改 `RLock`（migrate 外层与助手共用锁防死锁）。

## 3. 测试样本数字（tests/test_storage_migration.py，8 条全绿）

- 构造 4 类旧介质样本（2 书源 / 3 书架项 / 2 搜索结果 / appearance 键）→ migrate → 主库对应行数一致、字段无损、`.legacy-bak` 存在、二次 migrate 零新增、SourceService 保存后主库可见而旧 JSON 不再写。

## 4. 读取仲裁（两路径共存期）

续读进度以 **`books` 表（M2 结构化列）为唯一权威**；`bookshelf.reading` JSON 块仅作无 books 记录时的回退展示；两条读取路径共存到 M7 删除旧模型。

## 5. 收敛对照（§6.1 7 介质 → §6.2 3 类）

| 原介质 | 收敛后 |
|---|---|
| bookSource.json / bookshelf.json / appearance.json / cookie 文件 / search-books.sqlite3 / 规则状态 JSON | SQLite 主库（legado.db：settings/cookies/books/bookmarks/search_books/book_sources/bookshelf/rss/replace_rules/dict_rules/fonts/download_tasks/audit_log/tts_profiles） |
| reader-cache/ + chromium-profile*/ | 文件目录（reader-cache/downloads/image-cache/chromium-profile） |
| 互操作 JSON（导入导出/备份恢复） | 仅生成消费，不落地持久 | 

**注**：实际用户数据迁移发生在应用首次启动（`migrate()` 自动执行）；上述数字为测试样本验证结果。
